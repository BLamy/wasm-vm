# Explicit retained scanout proof

`createVirglScanoutBridge` extends the isolated submission proof with global scanout binding and retained frame tickets. Default negotiation and the existing control/submit factories remain unchanged.

`SET_SCANOUT` validates full-resource RGBA8 renderer textures before replacing the global generation-bound lease. A `RESOURCE_FLUSH` issues a PIXEL_PACK_BUFFER snapshot and polls a fence with zero flags and zero timeout outside Machine.run. After GPU readiness, RGBA rows are converted once to the established top-down BGRA frame format and accepted by the bounded presenter. Only then is guest completion posted. Actual canvas drawing has its own exactly-once drawn/superseded/cancelled/failed receipt.

The presenter uses the existing built PresentationController with scheduling disabled. Its own single pending frame and animation callback correlate actual same-call `onPresent.drawn`. Rebind, disable and reset cancel obsolete pending frames and clear retained recovery pixels. Invalid rebind leaves the old binding intact. Accepted frames survive public unref and numeric ID reuse; future lookup still requires the current public generation and a new successful bind.

Capture bytes are CPU-visible copies. Diagnostics count PBO collection, in-place channel/row conversion, the borrowed 2D frame copy, controller ownership copy, backend staging and presentation upload. This is not a zero-copy path. Renderer captures remain at most 4 MiB; ordinary 2D retains its existing 16,384-dimension / 256 MiB resource bounds. One capture and one queued frame may coexist. The controller may retain one additional recovery frame until invalidation or replacement.

The `bindings.retainScanout` capability is trusted host-only and creates a global texture lease. `asyncAccess.beginScanoutRead` creates an immutable issued snapshot with its own allocation reference. It deliberately permits later content revisions and lease release, while the existing index/storage validation continues to require its original lease and content revision. Release/disposal revoke opaque tickets exactly once.

The recurring browser command is `node tools/verify-virgl-scanout.mjs --output <directory>`. Add `--sabotage orientation` to omit only the new row reversal in the served source. That control must fail `scanout canvas top-left RGBA`, while preserving the original and served source digests separately. The launcher checks actual hardware WebGL and uses the built sink modules, with original captured event161 and independent literal canvas pixels. The reports label this host-injected guest queue replay, not a live Mesa guest boot.

Copy diagnostics describe the successful presentation path; backend staging/ImageData/upload counts cover acknowledged drawn frames. Trusted injected backend failures are recorded separately and do not claim exact internal partial-copy byte counts. Presenter enqueue success is admission only, and the guest FLUSH response never claims physical display. The drawn receipt confirms the canvas backend reported drawing during that exact controlled callback, corroborated by actual canvas readback in acceptance.

The full gate is `make verify-E6-T11c`. Pass `VIRGL_SCANOUT_DESKTOP_IMAGE` and `VIRGL_SCANOUT_DESKTOP_ASSETS` explicitly: the immutable Epic5 E5-T18a image and its split, content-addressed publication are authenticated by digest before and after the one cold desktop boot. Optional `VIRGL_SCANOUT_EVIDENCE_DIR` selects a fresh evidence directory. The final clean-clone command is `python3 tools/virgl-command/scanout-cold.py --desktop-image <image> --desktop-assets <directory> --output <fresh-directory>`; it passes these same authenticated external fixtures explicitly and scrubs inherited build overrides. No source-checkout default is used for the guest disk.
