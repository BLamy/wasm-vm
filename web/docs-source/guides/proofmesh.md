# The proposed ProofMesh layer

ProofMesh is a product proposal above the existing browser machine. Its specifications discuss passkey-owned encrypted volumes, verified peer delivery, and a builder/critic work market. The proposal is not a list of APIs already implemented by wasm-vm.

## Delivery order

1. Freeze schemas, threat models, canonicalization, verifier images, and evidence formats.
2. Prove a local builder/critic loop against a real workload.
3. Add encrypted overlay generations, credential and recovery slots, rotation, and revocation.
4. Add hash-verified delivery from HTTP, cache, and peer sources.
5. Establish diverse critic assignment, attestations, quorum, and challenge windows.
6. Introduce auctions, bounties, accounting, quotas, and abuse controls.
7. Consider process placement across browser nodes only after the storage and evidence boundaries hold.

## Preserve the current boundary

The guest executes locally. The current copy-on-write overlay is not the proposed encrypted volume. The existing provider transport is not proof of a peer distribution network. Recorded acceptance remains the currency for each product surface.
