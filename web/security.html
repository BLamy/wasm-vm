Current boundaries

Artifact integrity

The loader checks named artifacts against their manifest digests. A hash match establishes byte identity; it does not establish that an artifact is safe or that the publisher is trusted.

Local guest execution

The browser runs the CPU and stores the configured local state. Boot downloads and optional network providers still communicate outside the tab.

Writable storage

The current chunked image overlay uses IndexedDB. It is not presented as the proposed passkey-encrypted volume.

Proposed key hierarchy

WebAuthn authenticates the user. Where WebAuthn PRF is available, credential-bound output can unwrap a random volume key through a key-encryption key. Generation and shard keys sit below that volume key.

Multiple credentials and encrypted recovery slots are first-class requirements. Rotation and revocation need acceptance tests; losing the only credential cannot be handled by an unexplained recovery promise.

Peer distribution

The proposal separates immutable base-image blocks from authenticated encrypted user overlay generations. Peers transport bytes; manifest identity and digests establish what those bytes mean. Sharing local-only, invited-peer, or public ciphertext is an explicit policy decision.

Demand paging, cancellable read-ahead, generation parents, and replay/rollback checks belong to the future delivery boundary. None is a claim that the whole peer network ships today.

Layered AI isolation

A proposed hosted deployment places the agent inside wasm-vm, the browser inside a Firecracker microVM, and narrow policy controls around the interfaces. Read the AI Sandboxing architecture study →

Threat-model limits

  • A compromised page can see plaintext while a guest is unlocked.
  • Encryption does not conceal shard sizes, timing, or popularity.
  • Peers may retain published ciphertext indefinitely.
  • Cryptography cannot repair a weak benchmark or an ambiguous acceptance rule.
