## Goal
Make the guest/UI request fence deterministic and independently testable before it is wired to a
slow browser boot: unique request IDs, guest-computed end markers, echo stripping, byte-stream
parsing, and structured exit results.

## Context
The bridge runs over one ttyS0 stream, so a parser bug can cross-contaminate requests or hang every
later command. `web/guest-rpc.js` is the pure seam extracted from `main.js`; it must stay independent
of WasmMachine, DOM state, and browser timing.

## Deliverables
- `web/guest-rpc.js` framing/parse helpers (`stripConsole`, `endMarkerRegex`, `formatRpcCommand`,
  `createFencedRpc`).
- `web/tests/guest-rpc.test.mjs` deterministic tests for the parser and command formatter.

## Acceptance criteria
- [ ] The exact-id marker is required; a wrong-id marker and the echoed `%s` formatter cannot settle
      a request.
- [ ] Markers split across feeds, ANSI/CR noise, a 100,000-line burst, and non-zero guest exits are
      handled without dropped output or a hang.
- [ ] `cd web && node --test tests/guest-rpc.test.mjs` passes with the adversarial cases above.

## Adversarial verification
Feed wrong-id, truncated, split, regex-special, and command-echo lines in arbitrary chunks. Mutate
the parser to accept any `__WVEND_` line or to use a host-computed exit code; the deterministic suite
must fail. Confirm the module has no DOM or WasmMachine dependency.

### 2026-09-02 — fresh adversarial verifier — VERDICT: refuted

- **HELD — exact-id, wrong-id, truncation, regex-special, echo, burst, and ordinary non-zero cases.**
  Predicted that a wrong request marker, a truncated marker, a regex-special near miss, the echoed
  `%s` formatter, and a 100,000-line burst would not settle the wrong request or lose output, and that
  exit 1 would be surfaced. The committed suite passed 10/10 via `cd web && node --test
  tests/guest-rpc.test.mjs`; a fresh verifier-only probe independently passed
  `wrong-id/truncated/split/regex-special/echo/burst/non-zero` (the burst used exactly 100,000 lines).
- **FAILED — arbitrary marker split with a multi-digit exit.** Predicted that feeding the valid marker
  in arbitrary chunks, including between the digits of exit `17`, would remain pending until the
  complete marker and then return `{stdout:"", exit:17}`. At exact head `cf392ab`, the verifier command
  `node --input-type=module` importing `web/guest-rpc.js` fed `cmd\\n__WVEND_multi_1`; it observed
  `{"stdout":"","exit":1}` with `settled=true`, and the subsequent `7\\n` was ignored. The
  failure is at `web/guest-rpc.js:26-47`: `/(\\d+)/` matches the currently buffered digit run without
  requiring the marker's terminating newline, so a byte-stream split inside a valid multi-digit guest
  exit corrupts the structured result. This contradicts the task's arbitrary-chunk / non-zero-exit
  framing requirement. Fix the parser to wait for the complete marker record, add a committed
  multi-digit split regression, and rerun the exact suite.
- **COVERAGE — insufficient for the claimed 100,000-line case.** The committed test named “100k-line
  burst” feeds 1,000 lines of 100 characters each, not 100,000 lines (`web/tests/guest-rpc.test.mjs:67-77`).
  The fresh verifier probe did exercise exactly 100,000 lines and passed, so this is not a second
  runtime refutation; the committed suite's claim is not independently sufficient for that exact
  case until the regression test is corrected.
- **HELD — module independence.** `web/guest-rpc.js` has no DOM, `WasmMachine`, `window`, or browser
  imports; the source diff from implementation commit `c73b54f` is limited to the pure parser and
  Node test module, with task metadata submitted at `cf392ab`.
