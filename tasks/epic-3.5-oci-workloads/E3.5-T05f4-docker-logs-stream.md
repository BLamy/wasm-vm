## Goal
Wire the Logs pane to the real `wvrun logs -f <id>` stream, preserving stream ownership across
navigation and re-render while making close/stop cancel the stream without stopping the container.

## Context
The bridge's serialized RPC and shutdown barrier are already verified in T05e2. This slice applies
that contract to a real container lifecycle and the Docker UI, where duplicate console listeners and
stale tail bytes can otherwise create fake or repeated log lines.

## Deliverables
- Logs pane backed by a real guest stream, with guest-computed container output and live follow state.
- Cancellation on close/navigation/unmount that ends only the stream, not the container.
- Re-render/re-attach bookkeeping that permits one active listener and no duplicate transcript lines.

## Acceptance criteria
- [x] A real detached busybox run produces `CONTAINED_42` in Logs via `wvrun logs -f <id>`; the marker
      is computed in the container and the stream reaches the UI from guest bytes.
- [x] Closing the Logs pane ends the stream while a fresh `ps -a` still reports the container running;
      stopping the container separately ends the follow stream with the confirmed exit state.
- [x] Re-rendering the live Logs pane does not double-attach, duplicate lines, or mix the stream tail
      into the next RPC.

## Adversarial verification
Navigate away and back repeatedly during a burst, stop the container while following, and issue a new
RPC immediately after cancellation. Count marker lines and inspect console errors for any duplicate,
stale, or re-entrant output.
