## Goal
Wire the tested framing core to the real busybox browser console so `wvmDemo.run`, `wvmDemo.stream`,
and `wvmDemo.hasContainerRuntime` are honest over the existing ttyS0/input path, including
re-entrancy-safe stream stopping and a truthful runtime-absent result.

## Context
Busybox boots quickly and exercises the mechanism without conflating it with Alpine's long boot or
the presence of `wvrun`. This is the bounded browser proof for serialization, marker-spoof
resistance, streaming, non-zero exits, and fail-closed behavior.

## Deliverables
- `window.wvmDemo.run(cmd)`, `.stream(cmd, onLine)`, and `.hasContainerRuntime()` wired through the
  real console callback and `sendInput` bridge.
- A Playwright spec covering busybox RPC, back-to-back ownership, streaming stop, non-zero exit,
  marker spoof, and runtime absence.
- Rebuilt browser artifacts when `web/` sources change.

## Acceptance criteria
- [x] The real busybox guest returns guest-computed `RPC_42`, separate `A_2`/`B_4` results, and
      exit 1 for `false`.
- [x] A live stream delivers successive guest lines; stopping it leaves the guest usable for a fresh
      RPC, with no re-entrant WasmMachine error.
- [x] A wrong-id `__WVEND_` line cannot end a request, and `hasContainerRuntime()` is false on the
      public busybox build.
- [x] The focused Playwright run passes with zero unexpected browser console errors.

## Adversarial verification
Issue two requests in the same microtask, print a forged marker, stop from inside `onLine`, emit a
large burst, and call the runtime probe on a guest without `wvrun`. Any interleave, dropped fence,
re-entrancy error, optimistic runtime result, or unhandled console error refutes the bridge.
