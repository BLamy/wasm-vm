## Goal
Build the Containers view as a real projection of `wvrun ps -a`, with Stop, Remove, Restart, and
refresh actions whose displayed state is reconciled from the guest rather than updated optimistically.

## Context
T05b supplies the container lifecycle manager and T05f2 supplies a real detached Run. This slice owns
the list and lifecycle controls; logs and exec get separate slices so their stream/TTY ownership can be
verified independently.

## Deliverables
- Parse-safe `wvrun ps -a` polling into status, image, name, id, uptime, and exit fields.
- Stop, Remove, and Restart actions wired to guest commands with progress and typed errors.
- Reconciliation after polling, reload, and an external terminal-tab lifecycle change.

## Acceptance criteria
- [x] After a real detached busybox Run, Containers shows the guest's id/name and `running` status from
      `wvrun ps -a`, not a UI-only placeholder.
- [x] Stop, Remove, and Restart change the view only after the corresponding guest command and a fresh
      `ps -a` confirm the new state; exited records remain inspectable until removed.
- [x] Killing/stopping the same container from the Terminal tab is reflected by the next bounded
      Containers refresh, with no stale optimistic `running` row.

## Adversarial verification
Race refresh with Stop and reload the tab after an external kill. Return malformed or non-zero `ps`
output: the UI must show a typed error and retain the last confirmed state, never fabricate a transition.

## Verification log
