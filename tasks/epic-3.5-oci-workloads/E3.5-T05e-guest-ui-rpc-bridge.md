> Alpine runtime/browser proof. This file is a planning container; the child tasks are authoritative.

## Goal
The plumbing between the browser Docker tab and the container-capable guest: (1) a `wvmDemo` method
that boots the ALPINE guest (which ships `wvrun` + baked bundles), and (2) a fenced request/response
protocol over the single ttyS0 console so the UI drives `wvrun ps/logs/run/exec` and parses STRUCTURED
results instead of scraping free-form text — plus one long-lived streaming channel for `logs -f` /
interactive `exec`.

## Context
Today `window.wvmDemo` (main.js:404) can only boot the busybox initramfs; Alpine boots only via DOM
buttons. And there is ONE serial console — no multiplexed exec channel — so honest multiplexing is
required: serialize discrete RPCs, fence each with a unique request id, and dedicate a streaming mode
for follow/interactive. The console tap (`onConsole`) and input bridge (`sendInput`, with the
documented re-entrancy `setTimeout(0)` guard) already exist and are the exact bytes xterm sees — this
task adds a parser/dispatcher on top, never a side channel. Fail-closed: if the guest isn't the Alpine
(wvrun-capable) image, the bridge reports that honestly (the public busybox build has no wvrun).

## Deliverables
- `wvmDemo.bootAlpine()` — boots the chunked Alpine guest (the `#boot-alpine` path) and resolves
  `{ok:true}` once at a shell, `{ok:false,error}` on a refused/failed boot (typed, no fallback).
- `wvmDemo.hasContainerRuntime()` — true only when `/usr/local/bin/wvrun` + `/opt/containers/index.json`
  are present in the booted guest (probed, not assumed).
- A fenced-RPC helper: `wvmDemo.run(cmd) → {stdout, exit}` that sends `cmd; printf '__WVEND_<rid>_%s\n'
  $?`, collects console bytes between the echoed command and the `__WVEND_<rid>` marker, strips the
  echo, and returns structured output. Serialized (a queue) so concurrent callers don't interleave on
  the one console.
- A streaming channel: `wvmDemo.stream(cmd, onLine) → {stop}` for `logs -f` and interactive `exec`
  (bidirectional for `-it`).
- Marker/id discipline: request ids are unique per call; a command's own echo cannot satisfy its END
  marker (the marker embeds `$?`, computed by the guest).

## Acceptance criteria
- [ ] Playwright (local Alpine assets): `wvmDemo.bootAlpine()` reaches a shell;
      `wvmDemo.hasContainerRuntime()` is true; `wvmDemo.run('wvrun ps')` returns parseable JSON lines;
      `wvmDemo.run('echo RPC_$((6*7))')` returns stdout containing `RPC_42` and exit 0 (guest-computed).
- [ ] Two RPCs issued back-to-back return their OWN outputs (no interleave) — the fencing/serialization
      is real (issue `echo A_$((1+1))` and `echo B_$((2+2))`, assert A→2, B→4 in the right results).
- [ ] `wvmDemo.stream('wvrun logs -f <id>', onLine)` delivers successive lines from a live container
      and `stop()` ends the stream without killing the guest.
- [ ] A non-zero exit is surfaced (`wvmDemo.run('false')` → exit 1, not swallowed).
- [ ] On the public busybox build (no wvrun), `hasContainerRuntime()` is false and the bridge says so
      — no pretense of a runtime that isn't there.

## Adversarial verification
Marker-spoof: a command that PRINTS a fake `__WVEND_...` line must not prematurely end another RPC (ids
are per-call random; the parser binds to the exact issued id). Backpressure: a command emitting a large
burst does not drop the END marker (the parser is byte-stream robust, not line-count bounded). Re-entrancy:
issuing an RPC from inside an `onConsole` callback respects the existing `setTimeout(0)` guard (no
"re-entrant call into WasmMachine"). Guest reboot mid-RPC → the pending RPC rejects with a typed error,
the queue drains, no permanent hang.

## Verification log

### 2026-08-01 — channel mechanism proven GREEN in a real browser (busybox); Alpine AC1 in progress

**Implementation** (`web/main.js`, `window.wvmDemo`, commit `19773e6`):
- `run(cmd)` — canonical name for the serialized fenced RPC (shares `guestExec`: sends
  `<cmd>; printf '\n__WVEND_<rid>_%s\n' "$?"`, unique per-call `rid`, END marker binds to the exact
  id + guest-computed `$?`; promise-chained so back-to-back callers can't interleave).
- `hasContainerRuntime()` — real in-guest probe (`test -x /usr/local/bin/wvrun && test -f
  /opt/containers/index.json`), fail-closed (false when absent). NOT the load-time asset guess.
- `stream(cmd, onLine) → {send, stop}` — long-lived follow/interactive channel for `logs -f` / `exec
  -it`: taps the real console, splits on newlines (ANSI/CR stripped), swallows the command echo.
  **Re-entrancy fix:** `send()`/`stop()` defer their `ui.typeBytes` via `setTimeout(0)` — a consumer
  typically calls `stop()` from inside `onLine` (which runs in the console-emit loop), and driving the
  machine synchronously from there trips the WasmMachine re-entrancy guard and drops the bytes
  (exactly the "no re-entrant call into WasmMachine" concern in the adversarial section). First test
  run caught this (Ctrl-C dropped, console error); the fix made it green.

**Playwright proof** (`web/tests/e3-t05e-guest-ui-channel.spec.js`), real interpreted RISC-V guest,
real console byte stream (`onConsole`) + real input bridge (`sendInput`) — markers are guest-computed
(`$((6*7))→42`), so a host-side literal echo cannot satisfy them.

Test 1 — **fenced RPC, serialization, streaming & fail-closed runtime (busybox)** — **PASS (1.3m,
RC=0)**, covering the runtime-agnostic ACs on the fast/reliable busybox userland:
- AC (run): `run("echo RPC_$((6*7))")` → stdout `RPC_42`, exit 0 (guest-computed).
- AC5 (fail-closed): `hasContainerRuntime()` === **false** on the busybox build (real in-guest probe).
- AC2 (fencing): back-to-back `run("echo A_$((1+1))")` / `run("echo B_$((2+2))")` → A→2, B→4, no
  cross-contamination.
- AC4 (non-zero exit): `run("false")` → exit **1**, not swallowed.
- Adversarial marker-spoof: `printf '__WVEND_deadbeef_0\n'; echo REAL_$((3+4))` → the fake
  wrong-id marker does NOT end the RPC; stdout `REAL_7`, exit 0.
- AC3 (streaming): `stream()` of a live 8-iteration emitter delivered successive `STREAM_0,1,2…` in
  order; `stop()` ended it and a fresh `run("echo ALIVE_$((5+5))")` → `ALIVE_10` proved the guest
  survived (stop() did not kill the shell). Zero console errors after the re-entrancy fix.

Test 2 — **hasContainerRuntime() true + `wvrun ps` (Alpine)** — the two container-runtime-specific
assertions (AC1). Uses the SAME bridge code (same `run`/`hasContainerRuntime` proven green above),

### 2026-08-03 — fenced-RPC parser extracted + hardened with deterministic node tests

The fence/parse logic `main.js`'s `guestExec` implements inline is now also a pure, node-testable
module `web/guest-rpc.js` (`stripConsole`, `endMarkerRegex`, `formatRpcCommand`, `createFencedRpc`).
`node --test web/tests/guest-rpc.test.mjs` (10 cases, green) proves the ADVERSARIAL contract
deterministically — previously only browser-covered:
- **marker-spoof**: a different rid's `__WVEND_other_0` printed as command output does NOT settle this
  RPC; only the exact-id marker does.
- the echoed `printf '…%s\n'` (ends in `%s`, no digit) can never satisfy the id's marker (`(\d+)`).
- marker split across feeds still matches (byte-stream robust, not line-count bounded); a 100k-line
  burst before the marker loses nothing.
- ANSI/CR stripped before matching; regex-special chars in an rid are escaped (no wildcard match);
  echoed command line stripped from stdout; non-zero exit surfaced.
The main.js wiring adopting this module + the Alpine boot bridge (`bootAlpine`) + Playwright remain the
open ACs. Run: `cd web && node --test tests/guest-rpc.test.mjs`.
