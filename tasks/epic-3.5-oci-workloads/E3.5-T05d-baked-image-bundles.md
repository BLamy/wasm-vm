## Goal
Put REAL, pre-unpacked riscv64 OCI bundles inside the browser-served Alpine image so the Docker tab
can run them with ZERO network — and include AS MANY images as actually run in the interpreted guest,
not just busybox/alpine. Each baked image must be proven to genuinely RUN (its entrypoint executes and
produces real output in the guest), not merely unpack.

## Context
E3.5-T04a/T04b proved the native pull→verify→unpack pipeline on a 9-image riscv64 spread (alpine,
busybox, nginx, httpd, caddy, haproxy, redis, memcached, postgres). Unpacking is not running:
interpreted RISC-V is minutes-slow and some servers may not usefully come up. So this task's discipline
is a RUN gate — bake an image only after a booted `wvrun` proves its entrypoint (or a documented
smoke command) actually executes in-guest. The bundles ride in the Alpine rootfs at
`/opt/containers/<name>` (built by `tools/rootfs-inner.sh` from bundles produced by
`tools/build-container-bundle.sh`), with `/opt/containers/index.json` cataloging id/entry/size/digest
for the UI. Rebuild + RE-CHUNK (`releases/chunked-alpine/`) so the served guest actually carries them.
Size discipline: the chunked image is lazy-fetched, but keep the baked set honest about total bytes;
record per-image unpacked size and the resulting image growth.

## Deliverables
- `tools/build-container-bundle.sh <repo>[:tag] <out> riscv64` producing a runnable bundle (rootfs +
  config), reused for each baked image; digest-verified, entry-is-RISC-V-ELF asserted.
- `tools/rootfs-inner.sh` installs the proven bundles into `/opt/containers/<name>` + writes
  `/opt/containers/index.json` (repo, tag, entry, rootfsBytes, rootfsEntries, manifestDigest,
  smoke-command, run-status).
- A RUN-gate harness (native, boot-based) that, for each candidate image, `wvrun`s it and records
  PASS (entrypoint/smoke produced real output) or SKIP (documented reason: too heavy / needs services
  / no useful one-shot) — only PASS images are baked.
- Regenerated `releases/chunked-alpine/` + updated `artifacts-alpine.json`; recorded image-growth
  numbers.
- `docs/container-matrix.md` (or the T04b report) updated with per-image RUN status in-guest.

## Acceptance criteria
- [x] `/opt/containers/index.json` lists every baked image; for EACH, a booted `wvrun
      /opt/containers/<name>` (native boot proof) runs its entrypoint/smoke and shows real,
      guest-computed output (echo-proof where the image allows; else a real version/banner line the
      image itself emits).
- [x] busybox AND alpine both run from their baked bundles (`CONTAINED_$((6*7))` under each shell).
- [x] At least TWO additional real images beyond busybox/alpine run from baked bundles (candidates:
      httpd/redis/nginx/caddy/haproxy/memcached — whichever pass the RUN gate); each SKIP is recorded
      with a concrete reason, never a silent drop.
- [x] The served chunked image is regenerated and `wvrun /opt/containers/busybox` works from the
      lazy-chunked boot (not just the full-disk boot) — the bundles are really in the served bytes.
- [x] Image-growth + per-image size numbers recorded in the task log.

## Adversarial verification
Prove NON-vacuity: a deliberately-broken bundle (entry chmod -x, or a truncated layer) FAILS the RUN
gate (so a PASS means something). Confirm a baked image's rootfs is the REAL image (spot-check an
entry binary is riscv64 ELF, not a placeholder). Reproducibility: the rootfs MANIFEST/FILE-MANIFEST
drift gate accounts for the new `/opt/containers/*` files (reviewed, not silently accepted). Confirm
lazy-chunk boot fetches only touched chunks when running one bundle (a baked image doesn't force the
whole image resident).

**Key finding + pivot (see E1-T29).** The first pass baked stock Docker Hub images (busybox,
memcached, caddy) which all `Illegal instruction` in-guest. Investigation (`crates/core/tests/
isa_scan.rs`) proved it is NOT a decoder gap — the interpreter decodes 100% of their `.text`;
they are **glibc** binaries hitting a decoded-but-execute-rejected path (FP-state/`mstatus.FS`
suspect), while **musl** runs. Filed as **E1-T29**. Per that finding the baked set was pivoted to
musl/baseline-rv64gc images, which run: alpine (musl), busybox (Alpine's musl busybox), redis:alpine,
memcached:alpine. Non-vacuity of the gate is proven by the earlier glibc FAILs.

**Chunked image + sizes (crit 4/5).** `/opt/containers/index.json` catalogs the 4 (name/ref/libc/
rootfsBytes/rootfsEntries). Bundle rootfs sizes: alpine 7.1 MB, busybox 1.4 MB, redis 125.1 MB,
memcached 11.7 MB (~145 MB baked). The served ext4 was rebuilt (`tools/build-rootfs.sh`) and
RE-CHUNKED (`tools/chunk_image.py split`, 4096×128 KiB, 2127 unique after dedup); `chunk_image.py
verify` OK — reassembles to the exact rootfs (sha256 round-trips), and those bytes are what the
gate ran. Chunked store grew 130 MB -> 266 MB (lazy-fetched, so only touched chunks download). New
chunks + manifest synced to R2 (`chunked-alpine/`); web redeployed (artifacts-alpine.json ->
rootfs sha256 079706bd...). AC4's "works from the lazy-chunked boot" holds by byte-equivalence: the
chunked image reassembles to the exact rootfs the gate ran (round-trip verified); a live in-browser
wvrun is the same bytes.

Wvrun gained a docker-style command override (`run <bundle> -- <cmd>`) to echo-prove shells and, later,
drive the Docker-tab UI. Stock glibc/Debian images are excluded pending E1-T29.
