## Goal
Rebuild the Docker tab (`web/docker.js`) into a real Docker-Desktop-style surface driven by the guest
runtime: browse baked images, PULL (honest: real in-guest pull when a network provider is configured,
else the baked set), RUN a container, see it in a Containers list with live status, VIEW its logs
streaming, and EXEC an interactive shell inside it — all through the real Alpine guest + `wvrun`, never
a simulated shell or canned output.

## Context
The current tab (E3.5-T05a) boots busybox and types one command — honest but not a lifecycle. With the
guest lifecycle (T05b), exec (T05c), baked bundles (T05d), and the RPC bridge (T05e) in place, the UI
becomes a thin, honest client over `wvmDemo.run/stream`. Preserve the T05a honesty guarantees exactly:
NO JS command interpreter, NO canned transcript, NO fabricated digest/state — every row and line comes
from the guest. Behave truthfully by build: on the public busybox-only deploy (no wvrun),
`hasContainerRuntime()` is false → the tab shows the images catalog + an honest "container runtime runs
on the local Alpine image; this public build boots busybox" banner, not a broken UI.

## Deliverables
- Images view: catalog from `/opt/containers/index.json` (real sizes/digests/entry). Each has Run +
  Inspect. **Pull**: if a provider is configured, runs the real in-guest pull and shows progress; else
  a clear "live pull needs a relay/tailscale provider — these images are pre-baked" state (no fakery).
- Run → `wvrun run -d` → the container appears in the Containers view.
- Containers view: live `wvrun ps -a` (status dot, image, name, id, uptime/exit); Stop / Remove /
  Logs / Exec / Restart actions wired to the guest.
- Logs pane: `wvrun logs -f <id>` streamed live; stop/close ends the stream, not the container.
- Exec pane: `wvrun exec -it <id> sh` — a real interactive shell (an embedded xterm or the shared
  terminal) whose input goes to the container and whose output streams back; exit returns to the list.
- All async actions show real progress + typed errors; the boot-the-Alpine-guest affordance is in-tab.

## Acceptance criteria
- [ ] Playwright (local Alpine assets, slow-boot budget): open Docker tab → boot Alpine → Images lists
      the baked set from the guest catalog → Run busybox → Containers shows it `running` → Logs pane
      streams its guest-computed marker (`CONTAINED_42`) → Exec pane runs `echo INEXEC_$((6*7))` and
      shows `INEXEC_42` from inside the container → Stop moves it to `exited`. Every value is
      guest-computed (echo-proof); the test also asserts the transcript is the guest's, not host JS.
- [ ] Static-source honesty asserts (as in `docker-busybox.spec.js`): `docker.js` contains no canned
      transcript / fake digest / JS shell; markers use `$((6*7))` (guest-evaluated), never a host
      literal the test also greps for.
- [ ] Pull with no provider shows the honest baked-set state (no spinner-that-lies, no fake layers).
- [ ] On the public busybox build, the tab renders the honest degraded surface (runtime-absent banner
      + catalog), never a broken or pretend-working lifecycle.
- [ ] Every Containers action reflects REAL guest state within a bounded time (status derives from
      `wvrun ps`, not an optimistic UI-only update that can diverge from the guest).

## Adversarial verification
Attempt to make the UI show state the guest doesn't have: kill a container from the terminal tab
(same guest) and confirm the Docker tab's next `ps` reflects it (no stale optimistic row). A Run that
fails in-guest surfaces the guest's real error, not a generic UI message. The Exec pane cannot leak the
guest shell (it must be `wvrun exec` into the container, verified by the container hostname/root, not a
bare guest shell). Re-render during a live logs stream does not double-attach or fabricate lines.
Cross-check with the E3.5-T05a spec that the anti-fakery guarantees still hold verbatim.
