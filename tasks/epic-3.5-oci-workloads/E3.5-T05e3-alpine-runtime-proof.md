## Goal
Prove the same structured bridge against the chunked Alpine image that actually ships `wvrun` and
the baked OCI catalog: programmatic boot reaches a shell, the runtime probe is true, and structured
guest commands work without falling back to busybox or a host-side simulation.

## Context
The original E3.5-T05e acceptance combined the fast channel mechanism with a slow interpreted Alpine
boot. The mechanism now has its own child; this task owns only the Alpine-specific capability and
the exact browser evidence that the runtime is present.

## Deliverables
- `wvmDemo.bootAlpine()` using the chunked Alpine boot path with typed refused/failed outcomes.
- Playwright coverage for Alpine boot, `hasContainerRuntime() === true`, parseable `wvrun ps`, and a
  guest-computed RPC marker.
- Exact-head browser evidence and rebuilt/deployable artifacts for the changed browser path.

## Acceptance criteria
- [ ] `wvmDemo.bootAlpine()` reaches a shell on local Alpine assets and returns `{ok:true}`.
- [ ] The guest probe returns true only with `/usr/local/bin/wvrun` and
      `/opt/containers/index.json`; `wvmDemo.run('wvrun ps')` exits 0 with parseable JSON lines.
- [ ] `wvmDemo.run('echo RPC_$((6*7))')` returns guest-computed `RPC_42` with exit 0, and no
      busybox fallback or host-generated transcript is used.
- [ ] The focused Alpine Playwright run has zero unexpected browser console errors.

## Adversarial verification
Run against the public busybox-only build and a chunk manifest missing one runtime artifact:
boot/runtime detection must fail closed. Interrupt/reject the boot while an RPC is pending and verify
the promise rejects with a typed error and the queue does not hang. Inspect the transcript and
`wvrun ps` output for guest provenance.
