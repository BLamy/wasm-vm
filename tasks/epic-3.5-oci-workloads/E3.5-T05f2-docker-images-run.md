## Goal
Replace the Docker tab's image constants and Run wiring with a thin client over the booted guest:
load the baked catalog from `/opt/containers/index.json`, inspect real metadata, and start a real
detached `wvrun run` without inventing a container row or transcript.

## Context
T05f1 supplies the booted, capability-gated Alpine session. This slice owns only the Images view and
the command that initiates a detached run; the live Containers view and later actions are T05f3.

## Deliverables
- Guest-backed Images catalog with real image, digest, size, entrypoint, and bundle metadata.
- Inspect details that identify the guest bundle and exact command/provenance.
- Run action that issues real `wvrun run -d --name …` through the bridge and reports the guest result,
  including a typed in-guest error when the command fails.

## Acceptance criteria
- [ ] In a local Alpine Chromium run, Images rows equal the guest catalog returned from
      `/opt/containers/index.json`; Inspect shows the returned metadata, not duplicated fake values.
- [ ] Running the baked busybox image issues real detached `wvrun run -d`, returns the guest-created
      container identity, and does not mark the UI running until the guest accepts the command.
- [ ] A deliberately failed Run displays the guest's non-zero/error result and leaves no optimistic
      container state behind.

## Adversarial verification
Tamper with one catalog field and force a failed `wvrun run`; the UI must display the guest response and
not fall back to a hardcoded image or canned success. Repeat Run with a duplicate name and verify the
typed duplicate-name failure is preserved.
