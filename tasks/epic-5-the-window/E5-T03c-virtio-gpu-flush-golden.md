## Goal

Implement `RESOURCE_FLUSH` and finish the core presentation seam: a test sink records damage
rects and pixel CRCs, a null sink supports headless boots, and an independent reference path
proves the complete create → backing → scanout → transfer → flush flow.

## Deliverables

- Typed little-endian flush support with full damage-rectangle validation and bounded queue
  responses.
- `TestSink` recording `(scanout, rect, CRC32, resource dimensions)` and a null sink that
  accepts headless flushes without retaining pixels.
- Legal forwarding of a flush for a resource that is not currently scanout-bound, while a
  flush after `SET_SCANOUT(resource_id = 0)` carries no scanout binding.
- Five checked-in golden test patterns generated by an independent Rust reference path,
  including full-frame, partial, odd-x, multi-entry, and edge-touching damage cases.

## Acceptance criteria

- The end-to-end native test produces CRC-identical output to the independent reference for
  all five patterns and records the exact damage rectangle at the sink.
- `RESOURCE_FLUSH` on an unbound live resource succeeds and is forwarded with its dimensions;
  after scanout 0 is disabled, flushing the old resource still succeeds but produces no
  scanout-bound sink event.
- Malformed or out-of-bounds flush rectangles return `ERR_INVALID_PARAMETER` without a host
  panic, and the null sink permits a headless device path.
- The same golden results pass in the wasm32 test runner and native core tests; no browser
  presentation code is required in this slice.

## Adversarial verification

Replay flushes before binding, after unbinding, after `UNREF`, and with every boundary edge
just outside the resource. Mutate the golden fixture and prove the independent reference
comparison fails, then restore it. Confirm the sink receives a copied/owned pixel view rather
than a mutable alias of guest backing, and that no BGRA/RGBA swizzle appears in the core.
