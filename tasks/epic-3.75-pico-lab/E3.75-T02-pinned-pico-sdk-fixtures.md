## Goal
Produce byte-reproducible RP2350 RISC-V ELF, BIN, and UF2 fixtures so emulator behavior is tested
against real Pico SDK output rather than hand-authored instruction words alone.

## Context
The Pico SDK selects this target with `PICO_PLATFORM=rp2350-riscv`. Toolchain and SDK drift can
change instructions, startup code, IMAGE_DEF metadata, and expected peripheral accesses, so the
fixture inputs and outputs must be content-addressed before implementation begins.

## Deliverables
- A pinned, checksum-verified toolchain/SDK recipe under `tools/pico/`.
- Minimal fixture sources under `guest/pico2/` for UART, GPIO, timer IRQ, multicore FIFO,
  DMA memcpy, and PIO waveform behavior, with USB stdio disabled.
- Reproducible ELF32, BIN, UF2, disassembly, section-map, and SHA-256 manifests under
  `guest/pico2/prebuilt/`.
- `make verify-E3.75-T02`, including an offline verification mode for committed fixtures.

## Acceptance criteria
- [ ] `make verify-E3.75-T02` validates every committed artifact, confirms ELF class 32 and
  RISC-V machine type, and checks UF2 family/target metadata.
- [ ] Two scrubbed clean builds from the pinned inputs produce identical artifact hashes.
- [ ] The disassembly inventory contains only extensions owned by E3.75-T04 through T11; any
  unexpected opcode fails with its address and owning fixture.

## Adversarial verification
Change the SDK revision, toolchain binary, compiler flags, board target, one UF2 block, and one
prebuilt byte independently. Each mutation must be detected. Build from a clean directory with
ambient `PICO_*`, `CFLAGS`, and `RUSTFLAGS` removed; a host-dependent hash refutes.
