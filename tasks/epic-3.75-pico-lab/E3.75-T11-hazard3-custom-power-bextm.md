## Goal
Implement the remaining non-interrupt Hazard3 custom extensions enabled by RP2350 so SDK and
boot-path code observe the real processor profile.

## Context
RP2350 enables Xh3power power-management CSRs/instructions and Xh3bextm bit-extract-multiple used
by the bootrom. Treating them as no-ops would let simple fixtures pass while violating sleep or
boot semantics. Xh3pmpm is owned separately by E3.75-T10b.

## Deliverables
- Decode/execute and CSR behavior for the RP2350-configured Xh3power and Xh3bextm versions.
- Hazard3-source-derived directed vectors plus power-state interaction tests.
- Trace names for every custom instruction/CSR, a live browser micro-test, and
  `make verify-E3.75-T11`.

## Acceptance criteria
- [ ] `make verify-E3.75-T11` matches the pinned Hazard3 oracle in native and wasm32 builds.
- [ ] Bit extraction covers every mask population and boundary position without host-width leaks.
- [ ] Sleep/clock-request state wakes only on documented events.
- [ ] Unknown custom encodings/CSRs trap; the browser panel marks the custom profile `live`.

## Adversarial verification
Exhaust mask patterns for Xh3bextm and inject wake events before, during, and after sleep entry.
Disable each custom extension in the oracle comparison to prove the suite distinguishes it. A
benign-no-op implementation, hidden RV64 dependency, or nondeterministic wake refutes.
