## Goal
Deliver RP2350's 52-line, 16-priority Hazard3 interrupt controller, including nested preemption
and its array-CSR interface over standard `mip.meip`.

## Context
RP2350 does not use the Linux machine's PLIC. Xh3irq adds `MEIEA`, `MEIPA`, `MEIFA`, `MEIPRA`,
`MEINEXT`, and `MEICONTEXT`; incorrect window indexing, acknowledge, or priority handling will
break every interrupt-driven Pico SDK peripheral.

## Deliverables
- A per-hart Xh3irq controller with 52 external inputs, 16 priorities, force/enable/pending
  arrays, next-IRQ selection, context save/restore, and nested preemption.
- Exact CSR window semantics and standard MEIP integration.
- Datasheet/Hazard3-derived tests, trace events, browser micro-test, and
  `make verify-E3.75-T12`.

## Acceptance criteria
- [ ] `make verify-E3.75-T12` passes frozen Hazard3 IRQ vectors natively and under wasm32.
- [ ] Simultaneous IRQs resolve by documented enable, priority, nesting, and tie rules; masked
  IRQs remain pending and become visible when enabled.
- [ ] CSR array reads/writes affect only the selected 16-bit window; out-of-range lines cannot
  alias a valid IRQ.
- [ ] MEIP, MSIP, and MTIP ordering and vector entry match RP2350; the browser panel reports
  Xh3irq `live`.

## Adversarial verification
Drive every IRQ line, every priority, equal-priority ties, forced IRQs, nested handlers, and
enable/disable races at instruction boundaries. Compare the event sequence to the pinned RTL
oracle and sabotage a tie rule. One dropped/duplicated acknowledge or wrong handler nesting
refutes.
