## Goal
Select the supported RISC-V IMAGE_DEF from committed flash and enter the application through a
documented host-assisted RP2350 boot handoff.

## Context
Full USB bootloader and secure-boot ROM execution are outside this epic. The compatibility
boundary is the non-secure single-image RISC-V form: validate its metadata, establish documented
reset/translation state, and jump where the ROM would hand off without claiming excluded ROM
behavior.

## Deliverables
- A bounded IMAGE_DEF scanner/parser and deterministic selection rule for the scoped image form.
- Validated architecture, entry, image range, translation parameters, and initial core/register
  state.
- An auditable synthetic boot-handoff trace event and explicit unsupported-ROM API behavior.
- Paired ELF/UF2, browser live tests, and `make verify-E3.75-T17b`.

## Acceptance criteria
- [ ] `make verify-E3.75-T17b` reaches the same application-entry snapshot from the pinned UF2
  and paired direct ELF in native and wasm32 runs.
- [ ] Missing, ambiguous, malformed, Arm, signed/secure, partitioned, or out-of-range IMAGE_DEF
  inputs fail before core/reset/translation state changes.
- [ ] Every intentional deviation from real ROM execution is recorded in the compatibility
  ledger; unsupported ROM calls never succeed.
- [ ] The browser marks IMAGE_DEF boot `live` with zero console errors.

## Adversarial verification
Place candidate definitions at first/last scan offsets, create competing versions, corrupt each
field, and request every excluded boot feature. Compare pre/post failure snapshots and paired
ELF/UF2 handoff state. Any architecture confusion, partial reset, or unexplained ROM shortcut
refutes.
