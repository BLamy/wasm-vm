## Goal
Represent both RP2350 Hazard3 cores, hold core 1 in its documented reset/launch state, and execute
them under one deterministic scheduler with shared memory and devices.

## Context
RP2350 is symmetric dual-core. Parallel browser workers are not required for correctness and
would complicate replay, so the first model uses a deterministic event/interleave policy while
preserving a future worker boundary. SIO launch and synchronization land in the next task.

## Deliverables
- Two independently resettable harts with correct hart/core IDs, local CSRs, Xh3irq, timers,
  sleep state, and shared bus access.
- A deterministic round-robin/event scheduler with explicit tie-breaking, step budgets, and
  per-hart trace records.
- Reset/halt/WFI/interrupt interleave tests, snapshot support, chaos recordings, and
  `make verify-E3.75-T22`.

## Acceptance criteria
- [ ] `make verify-E3.75-T22` produces identical multi-hart traces and snapshots across repeated
  native, wasm32, and independent scheduling-chunk runs.
- [ ] Core 0 boots while core 1 remains inactive until an explicit launch transition; per-core
  reset affects only documented local/shared state.
- [ ] Shared writes become visible in the defined order and wake/interrupt delivery targets the
  correct hart.
- [ ] Linux `virt` remains single-hart by default and its frozen results do not change.
- [ ] The browser runs a two-hart scheduler micro-test, marks dual-core execution `live`, and
  reports zero console errors.

## Adversarial verification
Vary execution quantum, arrange same-event writes/interrupts/resets, hold one hart in WFI, and run
Linux rr chaos recordings of shared-state tests. Any result dependent on host thread timing,
misattributed trace, cross-core CSR leak, or unrecorded scheduler choice refutes.
