## Goal
Execute one RP2350 DMA channel's programmed bus transfers exactly, including address generation,
width conversion, partial progress, errors, and reservation invalidation.

## Context
The data-movement engine is separable from sixteen-channel arbitration, DREQ pacing, chaining,
and shared IRQs. Proving it first makes every beat observable and prevents scheduler complexity
from masking an address or fault bug.

## Deliverables
- Channel address/count/control state with byte/halfword/word widths, increment/reverse/ring
  modes, byte swap, zero count, trigger, busy, and typed read/write errors.
- Deterministic per-beat bus events connected to the global exclusive monitor.
- Memory-copy, boundary, fault, abort-at-beat, snapshot, browser, and native/wasm tests.
- `make verify-E3.75-T24a`.

## Acceptance criteria
- [ ] `make verify-E3.75-T24a` passes frozen single-channel register, transfer, error, and state
  vectors natively and under wasm32.
- [ ] All widths, increments, reverse/ring wrap, zero count, unaligned addresses, and region-end
  faults have exact asserted partial-progress outcomes.
- [ ] Every overlapping DMA write invalidates LR/SC and snapshot/restore never duplicates a beat.
- [ ] Unsupported security/MPU modes fail explicitly; the browser panel marks DMA transfers
  `live`.

## Adversarial verification
Cross-product widths/address modes at every map boundary, fault reads and writes on each beat,
abort and snapshot between read/write phases, and inspect coverage of every control-bit branch.
Any out-of-bounds access, repeated/lost beat, partial write outside the contract, or stale
reservation refutes.
