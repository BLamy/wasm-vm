## Goal
Implement the reset controller and deterministic clock-control behavior required for pinned Pico
SDK startup to configure the RP2350 RISC-V machine and reach `main`.

## Context
SDK startup touches resets, clock muxes/dividers, and XOSC/ROSC/PLL status before application
peripherals. Browser emulation must expose stable logical lock/selected states without pretending
to simulate oscillator analog behavior. Full watchdog/tick semantics are owned by E3.75-T20b;
this task may expose only the explicit reset-value shell needed to reach that later boundary.

## Deliverables
- RP2350 reset-controller and startup clock-register models for the exact in-scope SDK path.
- A documented deterministic frequency-domain/event conversion policy and reset propagation
  contract for cores and devices.
- An MMIO access ledger proving the startup fixture reaches `main` with no unknown read/write.
- Native/WASM/browser tests and `make verify-E3.75-T16`.

## Acceptance criteria
- [ ] `make verify-E3.75-T16` boots the pinned direct-load startup fixture to `main` with the same
  MMIO trace and state digest natively and under wasm32.
- [ ] Reset assert/deassert, reset-done, mux selected, PLL lock, divider, and full-machine reset
  behavior match the documented model; watchdog-owned accesses are identified, not swallowed.
- [ ] Unsupported oscillator/clock modes return explicit errors or documented fixed values, not
  hangs or nondeterministic host time.
- [ ] The browser capability panel marks RP2350 startup clocks `live` with zero console errors.

## Adversarial verification
Reorder reset and clock writes, request impossible sources/dividers, reset during peripheral
activity, and repeat under different host timing. Inspect the MMIO ledger for swallowed accesses.
Any dependence on `Date.now`, a stuck SDK poll, or state surviving a documented reset refutes.
