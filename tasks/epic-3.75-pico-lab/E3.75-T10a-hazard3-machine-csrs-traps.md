## Goal
Implement the standard privileged architecture as configured by RP2350 Hazard3: M/U modes,
Zicsr/Zifencei, precise exceptions, interrupts, and architectural counters.

## Context
The Linux RV64 hart includes S mode, delegation, page translation, and a different CSR profile.
Pico firmware needs a smaller but observably different machine: Hazard3 hardwires `mtval` to zero,
has RP2350-specific `misa`/ID values, and uses machine-mode vectors and WFI behavior.

## Deliverables
- A Hazard3 CSR/reset profile with exact legal masks, IDs, counters, `mret`, `wfi`, and exception
  entry/return behavior.
- Profile-specific trap priority, vectoring, counter access/wrap, and `fence.i` behavior.
- Directed privilege/trap tests, pinned Hazard3 comparisons, browser fixture, and
  `make verify-E3.75-T10a`.

## Acceptance criteria
- [ ] `make verify-E3.75-T10a` matches pinned Hazard3 CSR/trap vectors and official RV32
  privilege tests in native and wasm32 builds.
- [ ] `mtvec` alignment/vectoring, interrupt enable stacking, `mepc`, hardwired-zero `mtval`,
  `minstret`/`mcycle`, illegal CSR accesses, WFI wake, and M/U transitions are exact.
- [ ] No S-mode/Sv39 state leaks into the Hazard3 profile; RV64 privilege goldens do not drift.
- [ ] The built browser passes both suite totals with zero console errors and marks traps/CSRs
  `live`.

## Adversarial verification
Attack CSR aliases and WARL bits, nested trap entry, vectored alignment, counter wrap, M/U
transitions, WFI wake, and self-modifying code around `fence.i`. Predict state before inspecting
traces. Any silent unsupported CSR, non-precise fault, or RV64 profile contamination refutes.
