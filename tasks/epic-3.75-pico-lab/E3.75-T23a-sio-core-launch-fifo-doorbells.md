## Goal
Run Pico SDK's core-1 launch protocol and bounded inter-core messaging on the two emulated
Hazard3 harts.

## Context
SIO exposes per-core CPUID, bidirectional FIFOs, status/error flags, doorbells, and interrupt
signals. Each operation must be one indivisible scheduler event; host callback ordering cannot
choose whether a message or wake is observed.

## Deliverables
- Per-core CPUID, bounded bidirectional FIFOs, status/error bits, read/write semantics, and IRQs.
- Doorbell set/clear/status and the documented core-1 reset/launch handshake.
- Pico SDK launch and FIFO ping-pong fixture, varied-quanta tests, rr chaos evidence, browser
  micro-test, and `make verify-E3.75-T23a`.

## Acceptance criteria
- [ ] `make verify-E3.75-T23a` launches core 1 with the pinned SDK API and completes a FIFO
  ping-pong with identical native/WASM transcript and trace digest.
- [ ] FIFO full/empty, overflow/underflow, doorbell set/clear, IRQ, reset, and relaunch outcomes
  match the asserted datasheet vectors.
- [ ] Equal-event producer/consumer operations follow the documented scheduler order at every
  execution quantum.
- [ ] The browser panel marks multicore messaging `live` with zero console errors.

## Adversarial verification
Fill/empty FIFOs on equal events, reset core 1 during each launch word, ring/clear doorbells
concurrently, vary quantum, and replay Linux rr chaos traces. A lost/duplicated word, lost wake,
unbounded queue, stale relaunch state, or host-order dependence refutes.
