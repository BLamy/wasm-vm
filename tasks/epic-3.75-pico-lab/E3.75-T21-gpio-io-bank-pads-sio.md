## Goal
Model all 30 RP2350A GPIOs plus the Pico 2 board wiring: 26 header GPIOs and the four internal
GPIO23/24/25/29 functions, from pad input through SIO output and per-core interrupts.

## Context
The non-wireless Pico 2 exposes GPIO0–22 and GPIO26–28 on its header. GPIO23 controls SMPS mode,
GPIO24 senses VBUS, GPIO25 drives the onboard LED, and GPIO29 senses VSYS/3. Firmware configures
pads and IO_BANK0, then uses SIO SET/CLEAR/XOR and reads pin state. PIO will attach to the same
fabric later; there must be one authority for resolved pin state and board wiring.

## Deliverables
- A 30-GPIO fabric with external input only on board-accessible pins, internal board signals,
  pulls, input enable, output enable/value, function select, overrides, and conflict policy.
- IO_BANK0/PADS_BANK0/SIO registers, atomic aliases, and per-core edge/level IRQ state wired to
  Xh3irq.
- Timestamped pin transition events and SDK blink/IRQ fixtures.
- Browser live test and `make verify-E3.75-T21`.

## Acceptance criteria
- [ ] `make verify-E3.75-T21` matches frozen register, IRQ, and pin-transition traces in native
  and wasm32 runs.
- [ ] SET/CLEAR/XOR, direction, pulls, overrides, edge latching/ack, level reassertion, and
  per-core masks behave exactly at all 30 pins.
- [ ] Inputs injected at equal timestamps have a documented total order and replay identically.
- [ ] The SDK blink fixture drives GPIO25/LED; header stimulus cannot directly drive internal
  GPIO23/24/25/29; GPIO reports `live` in-browser.

## Adversarial verification
Toggle every pin around direction/function changes, inject simultaneous rising/falling edges,
ack while level remains active, and route masks differently to both cores. Attack out-of-range
pins and drive conflicts. Any cross-pin bit leak, lost latched edge, or host-order dependence
refutes.
