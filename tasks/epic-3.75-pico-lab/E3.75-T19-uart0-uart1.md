## Goal
Run Pico SDK UART stdio and interrupt-driven serial I/O through both RP2350 UART instances with
bounded FIFOs and deterministic timing.

## Context
The existing 16550 device is not the RP2350 UART register model. Pico SDK observes data/flag,
baud-divider, line-control, FIFO, mask/status/clear, and DMA-request behavior; the capstone uses
UART0 for its exact transcript.

## Deliverables
- Two independently addressed UART instances with register reset values, RX/TX FIFOs, divisor and
  line configuration, flags/errors, interrupt masks/status/clear, and host byte callbacks.
- Deterministic RX injection events and TX drain policy independent of wall-clock scheduling.
- SDK polling and IRQ fixtures, browser serial wiring, and `make verify-E3.75-T19`.

## Acceptance criteria
- [ ] `make verify-E3.75-T19` produces the frozen UART transcript and IRQ trace from both native
  and wasm32 runs.
- [ ] FIFO empty/full thresholds, overrun/error bits, masks, raw/masked status, and interrupt
  clearing match the datasheet vectors.
- [ ] UART0 and UART1 state/IRQs never alias; reset during queued traffic has the documented
  result.
- [ ] Browser input/output works in one load with zero console errors and UART reports `live`.

## Adversarial verification
Fill and drain at every threshold, inject bytes on the same event as reads/reset, vary divisors,
mask while pending, and flood beyond capacity. Predict IRQ transitions before reading the trace.
Dropped/duplicated bytes, unbounded queues, cross-UART leakage, or host-clock dependence refutes.
