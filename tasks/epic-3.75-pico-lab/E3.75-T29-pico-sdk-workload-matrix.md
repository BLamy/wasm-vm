## Goal
Run a fixed matrix of independently meaningful Pico SDK programs across direct ELF, UF2/XIP,
native, WASM, and browser paths before declaring the board complete.

## Context
A single showcase firmware can accidentally avoid broken registers or become self-licking.
The matrix separates startup, UART, GPIO IRQ, alarms, multicore, atomics, DMA, and PIO so each
failure has a narrow owner and each in-scope subsystem must contribute observable evidence.

## Deliverables
- A manifest-driven matrix containing at least `hello_uart`, `blink_alarm`, `gpio_irq`,
  `multicore_fifo`, `atomic_contend`, `dma_memcpy`, and `pio_dma_wave`.
- Per-workload instruction budgets and frozen UART, MMIO, IRQ, pin, trace, and state digests.
- One exact-head runner for native, wasm32, and browser; a cold-clone/offline fixture proof.
- `make verify-E3.75-T29`.

## Acceptance criteria
- [ ] `make verify-E3.75-T29` passes every workload in every applicable load/runtime path with
  zero quarantine, ignore, timeout, or unknown MMIO access.
- [ ] Direct ELF and UF2/XIP paths converge at the documented handoff checkpoint and then produce
  identical application-observable digests.
- [ ] Two cold runs and native/WASM/browser agree on every deterministic artifact.
- [ ] The browser reports the manifest-derived Pico total with zero failures/errors and all
  in-scope roadmap pips `live` or `verified`.

## Adversarial verification
Sabotage each subsystem independently and prove only the owning workloads fail; run independent
input seeds and scheduling quanta; inspect changed hunks against trace coverage; execute from a
pristine clone with scrubbed environment. A stale/self-generated golden, untested changed hunk,
or fixture requiring developer state refutes.
