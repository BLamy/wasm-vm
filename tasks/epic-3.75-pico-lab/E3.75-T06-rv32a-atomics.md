## Goal
Implement the complete RV32A word-width LR/SC and AMO instruction set with a reservation model
that can later attach to RP2350's global exclusive monitor.

## Context
RP2350 Hazard3 implements only 32-bit atomic memory operations. Reusing RV64A requires more than
truncating values: access width, alignment, reservation invalidation, acquire/release bits, and
fault atomicity must remain explicit, and RV64 doubleword atomics must be illegal.

## Deliverables
- RV32 `LR.W`, `SC.W`, and every `.W` AMO operation.
- A bus-facing reservation invalidation hook shaped for multiple harts and DMA writers.
- Directed, official-signature, native/wasm tests, Linux rr chaos recordings, and a live browser
  micro-test.
- `make verify-E3.75-T06`.

## Acceptance criteria
- [ ] `make verify-E3.75-T06` passes official RV32A signatures and an independent trace oracle.
- [ ] Overlapping hart or synthetic DMA writes invalidate reservations; non-overlapping writes do
  not; failed/faulting SC has no unintended memory effect.
- [ ] All `.D` atomic encodings trap illegal under RV32 and remain valid under RV64.
- [ ] The final exact-head LR/SC contention/invalidation test survives the prescribed rr chaos
  recordings with one result digest.
- [ ] The browser capability panel reports RV32A `live` with zero console errors.

## Adversarial verification
Attack subword overlap, address wrap, misalignment, intervening loads, faults between LR and SC,
and reservation state after traps/reset. Run independent randomized sequences against the model
and replay the Linux chaos traces, then sabotage invalidation. Any false-success SC, partial AMO
write, unrecorded scheduling sensitivity, or RV64 drift refutes.
