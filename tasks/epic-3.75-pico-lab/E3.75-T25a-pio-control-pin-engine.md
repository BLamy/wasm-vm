## Goal
Build all three RP2350 PIO blocks and execute their control-flow, wait, move, IRQ, set, side-set,
delay, wrap, and pin-timing behavior cycle-exactly.

## Context
Each block has four state machines sharing 32 instruction words. Separating control/pin timing
from shift/FIFO dataflow keeps this task bounded while establishing PIO's defining contract:
which pin changes on which emulated cycle.

## Deliverables
- Three blocks, twelve state machines, shared instruction memories, state-machine configuration,
  pin mapping, fractional clock divisors, enable/restart, and wrap.
- `JMP`, `WAIT`, `MOV`, `IRQ`, and `SET` with conditions, side-set, delay, and cycle trace.
- Standalone assembler vectors, multi-machine contention tests, browser micro-test, and
  `make verify-E3.75-T25a`.

## Acceptance criteria
- [ ] `make verify-E3.75-T25a` matches independent per-cycle vectors for every owned opcode in
  native and wasm32 builds.
- [ ] All twelve machines run independently while sharing only documented block state; instruction
  and pin-map boundaries are enforced.
- [ ] Divisor, WAIT stall, side-set/delay, wrap, restart, and simultaneous pin-write outcomes are
  exact and deterministic.
- [ ] The browser panel marks PIO control/pins `live` with zero console errors.

## Adversarial verification
Enumerate owned opcode fields/conditions, run multiple machines against the same pins,
self-modify instruction memory around fetch, and test divisor/wrap extremes. Compare every cycle
to an independent small-step model. One off-by-one pin transition or cross-block leak refutes.
