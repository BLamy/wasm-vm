## Goal
Implement the additional compressed Zcb operations and Zcmp push/pop/double-move instructions
used by RP2350's code-density profile.

## Context
Zcb shares operations with the bitmanip extensions, while Zcmp performs multi-register stack
updates with strict register-list and immediate rules. Incorrect partial writes on a fault would
corrupt startup or exception frames in ways ordinary output tests may not reveal.

## Deliverables
- Complete RP2350-configured Zcb and Zcmp decode/execute behavior.
- Generated legal/illegal encoding tables and directed stack-frame tests.
- Fault-atomic multi-register memory semantics with trace coverage.
- A live browser micro-test and `make verify-E3.75-T09`.

## Acceptance criteria
- [ ] `make verify-E3.75-T09` passes pinned Zc signatures and Hazard3 instruction vectors in
  native and wasm32 builds.
- [ ] Every legal push/pop register list and stack adjustment matches the oracle; reserved lists
  trap before any register or memory mutation.
- [ ] A fault on any multi-access instruction follows the documented architectural atomicity and
  leaves an exactly asserted state.
- [ ] The browser panel marks the Zc profile `live` with zero console errors.

## Adversarial verification
Enumerate all compressed encodings in the owned quadrants, inject faults at each memory access,
and attack stack wrap, return forms, and overlap with base C encodings. A decoder collision,
partial frame, or post-fault PC advance refutes.
