## Goal
Connect PIO state machines to their FIFOs, interrupt lines, DMA request signals, and the shared
GPIO fabric so real Pico SDK PIO programs can stream without host intervention.

## Context
The instruction engine alone cannot run normal SDK examples. Observable compatibility depends on
FIFO join modes and thresholds, CPU stall behavior, block IRQ flags, Xh3irq routing, and DREQ
backpressure across DMA and PIO at exact cycles.

## Deliverables
- TX/RX FIFOs for all twelve state machines, join modes, status/debug flags, blocking CPU
  accesses, and shift-engine coupling.
- Per-block IRQ flags/routing and RX/TX DREQ signals connected to Xh3irq and DMA.
- A DMA-fed PIO fixture emitting a frozen pin waveform plus underflow/overflow/backpressure tests.
- Browser live test and `make verify-E3.75-T26`.

## Acceptance criteria
- [ ] `make verify-E3.75-T26` produces the exact UART/log, DMA completion, IRQ, FIFO, and
  cycle-numbered pin digest in native and wasm32 runs.
- [ ] FIFO capacities, join transitions, blocking/nonblocking PUSH/PULL, thresholds, sticky
  debug flags, and IRQ clears match asserted datasheet vectors.
- [ ] DREQ starts/stops DMA at the documented threshold without a lost or duplicated word.
- [ ] The browser panel marks PIO streaming `live` with zero console errors.

## Adversarial verification
Cross every FIFO threshold in both directions, switch join modes around queued data, abort DMA on
a stalled beat, force/clear IRQs while state machines run, and contend multiple machines. Vary
scheduler quantum. Any word loss, extra pin cycle, deadlock, or native/WASM ordering difference
refutes.
