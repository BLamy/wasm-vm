## Goal
Prove the assembled RP2350 CPU profile as one whole before any board peripheral can hide CPU
defects behind higher-level output.

## Context
Individual extension suites do not prove cross-extension decode ownership, trap precision, or
determinism. The official RISC-V architectural tests and pinned Hazard3 RTL/source vectors form
the independent oracle; the same corpus must run through native and WASM interpreters.

## Deliverables
- `tools/pico/hazard3-gate.sh` running the owned RV32 architectural signatures, custom vectors,
  randomized differential streams, and illegal-encoding inventory.
- Frozen instruction-trace and architectural-state digests shared by native and wasm32 tests.
- A browser-visible per-extension result table and `make verify-E3.75-T13`.

## Acceptance criteria
- [ ] `make verify-E3.75-T13` reports every configured extension, privilege case, and Xh3irq case
  passed with zero quarantines or ignored tests.
- [ ] Identical seeds produce byte-identical native/WASM traces and final-state digests.
- [ ] Every 16- and 32-bit encoding in the owned spaces has exactly one decode owner or is
  explicitly illegal.
- [ ] The existing RV64 suite still reaches its current total with zero failures; all Pico CPU
  capability pips are `live`/`verified` in one browser load with zero console errors.

## Adversarial verification
Run independent seeds, mutate one result per extension, inject illegal/custom overlaps, and
compare changed decode/execute hunks to recorded coverage. A stale golden, ignored test,
unexercised semantic hunk, native/WASM divergence, or RV64 regression refutes.
