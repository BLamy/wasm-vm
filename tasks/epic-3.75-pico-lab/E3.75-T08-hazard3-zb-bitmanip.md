## Goal
Execute the standard bit-manipulation extensions configured on RP2350 Hazard3 cores at exact
RV32 widths.

## Context
The RP2350 datasheet names Zba, Zbb, Zbs, and Zbkb as part of its processor configuration.
Compiler-generated Pico SDK code may select these instructions even when simple examples do not,
so accepting only the observed fixture subset would create a fragile profile.

## Deliverables
- Decode/execute coverage for every instruction in the RP2350-configured versions of Zba, Zbb,
  Zbs, and Zbkb.
- Spec-version pins, golden decode tables, boundary/property tests, and oracle comparisons.
- A live browser bitmanip micro-test and `make verify-E3.75-T08`.

## Acceptance criteria
- [ ] `make verify-E3.75-T08` passes the pinned architectural signatures and Hazard3 vectors in
  native and wasm32 builds.
- [ ] Rotate, count, sign/zero extend, byte operations, bit index masking, and address-generation
  shifts match the frozen oracle for zero, all-ones, alternating, and one-hot inputs.
- [ ] Encodings outside the configured versions trap rather than aliasing to a nearby operation.
- [ ] The browser panel marks the Zb profile `live` with no RV64 suite regression.

## Adversarial verification
Generate exhaustive bit indices and property-check every operation against independent formulas;
cross-check overlaps between extension versions and RV64 encodings. Sabotage one index mask or
signed comparison and prove a permanent test fails. Any self-referential golden refutes.
