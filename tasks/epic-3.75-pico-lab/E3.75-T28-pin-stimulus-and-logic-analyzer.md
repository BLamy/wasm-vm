## Goal
Let users drive digital Pico pins and inspect GPIO/PIO output waveforms without introducing
browser timing nondeterminism.

## Context
Buttons and pin toggles are external machine inputs and therefore part of record/replay. A canvas
sampled by `requestAnimationFrame` cannot be the oracle; input and output must be timestamped in
emulated cycles, with rendering derived from the recorded event stream.

## Deliverables
- A versioned pin-input event format with emulated-cycle timestamps, deterministic tie-breaking,
  import/export, replay, and bounded storage.
- Browser header-pin controls for high/low/floating/pulse stimulus; internal board GPIOs remain
  read-only visual signals.
- A zoomable logic analyzer for selected pins, IRQ markers, and PIO/DMA events rendered from the
  canonical transition trace.
- `make verify-E3.75-T28`.

## Acceptance criteria
- [ ] `make verify-E3.75-T28` records one stimulus session, replays it natively and under wasm32,
  and obtains identical UART, IRQ, pin-transition, and final-state digests.
- [ ] Equal-cycle input/output events follow one documented order; floating/pull resolution and
  pulse boundaries match the GPIO model.
- [ ] Long idle spans are compact, trace memory is bounded, and export/import rejects corrupt or
  incompatible versions.
- [ ] Phone/tablet/desktop Playwright checks show the same logical transitions with zero console
  errors.

## Adversarial verification
Inject events at cycle 0, now, past, future, and the same cycle as GPIO/PIO writes and reset;
import hostile sizes/timestamps; background and resize while capturing. Any RAF/wall-clock
influence, reordered replay, unbounded growth, or visual transition absent from the canonical
trace refutes.
