## Goal
Decode and execute every RV32C/Zca instruction with RV32-specific legality, immediates, and
two-byte PC behavior.

## Context
The current compressed decoder is RV64C. Several quadrant encodings change meaning or legality
when XLEN is 32, and Pico SDK startup code uses compressed instructions heavily. One shared
decoder must not silently choose the RV64 form.

## Deliverables
- Profile-aware compressed decode/execute for the complete RV32C/Zca set.
- Exhaustive 16-bit decode classification plus directed execution/signature tests.
- A Pico SDK compressed smoke fixture in the live browser suite.
- `make verify-E3.75-T07`.

## Acceptance criteria
- [ ] `make verify-E3.75-T07` passes official RV32C signatures natively and under wasm32.
- [ ] Every 65,536 halfword value has a stable classification for RV32 and RV64; reserved forms
  trap without state mutation.
- [ ] Cross-page/region 16-bit fetch faults are precise and successful instructions advance PC
  by exactly two bytes.
- [ ] The browser suite reports RV32C `live` and the RV64C golden remains unchanged.

## Adversarial verification
Diff all halfwords against an independent decoder and focus on encodings whose RV32/RV64 meanings
differ, zero immediates, stack-pointer forms, link-register writes, and fetches at region ends.
One profile-confused decode or partial state update refutes.
