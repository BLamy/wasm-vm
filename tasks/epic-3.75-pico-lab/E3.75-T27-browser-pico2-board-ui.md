## Goal
Make the RP2350 machine a first-class browser experience: users can select Pico 2, drop a UF2,
run/reset it, see the board and LED/pins, and use a serial console.

## Context
The existing demo proves a Linux-style RV64 `virt` machine. Pico Lab needs a distinct composition,
not hidden test controls, while continuing to load the existing demo by default. The UI must
represent emulated state faithfully and avoid implying excluded peripherals are supported.

## Deliverables
- A Pico 2 machine selector and responsive board view with the 40-pin header, GPIO labels,
  onboard LED, run/pause/step/reset, speed, and UF2/ELF load controls.
- UART terminal/input, explicit boot/fault status, per-capability `live`/`verified`/`unsupported`
  states, and accessible keyboard/screen-reader labels.
- Object-URL/worker/listener teardown and a Playwright acceptance path.
- `make verify-E3.75-T27`.

## Acceptance criteria
- [ ] `make verify-E3.75-T27` builds and loads the page at phone, tablet, and desktop widths with
  zero console errors; the current RV64 suite still reaches its manifest total.
- [ ] Dropping the pinned UF2 reaches its UART checkpoint, changes the LED/pin view from actual
  emulator events, and reset returns the exact initial UI/machine state.
- [ ] Invalid files and unsupported capabilities produce specific recoverable errors without
  replacing the running machine.
- [ ] Repeated machine switching leaves no extra worker, listener, animation loop, or object URL.

## Adversarial verification
Drop wrong/huge/truncated files, switch machines during load/run, reset during UART output,
background/resume, and repeat lifecycle operations. Inspect accessibility tree and resource
counts. A decorative state not backed by emulator events, stale callback, console error, or RV64
demo regression refutes.
