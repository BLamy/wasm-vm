## Goal
Make register, PC, effective-address, shift-width, trace, and snapshot behavior explicitly
profiled by XLEN while preserving every existing RV64 result byte-for-byte.

## Context
The current hart stores RV64 architectural state directly in `u64` values and contains RV64-only
`*W` behavior. RP2350 needs RV32 wrapping and masking, but a broad fork of the interpreter would
duplicate bugs. This task creates the narrow abstraction boundary; it does not add RV32 opcodes.

## Deliverables
- An explicit RV64/RV32 architectural-width profile used by integer registers, PC updates,
  address arithmetic, shifts, canonical trace formatting, and snapshots.
- Compile-time or construction-time prevention of mixing a hart and machine with different XLEN.
- Regression and boundary tests for `0xffff_ffff + 1`, signed values, shift masks, PC wrap, and
  snapshot/trace widths.
- `make verify-E3.75-T03`.

## Acceptance criteria
- [ ] `make verify-E3.75-T03` passes the full existing RV64 native, wasm32, determinism, and
  riscv-tests gates with unchanged frozen digests.
- [ ] RV32 width helpers pass exhaustive boundary tests without making an RV32 instruction
  executable yet.
- [ ] No device model or Linux `virt` address is truncated by the refactor.
- [ ] One built-page load completes the current browser suite total with zero failures or console
  errors and records the unchanged roadmap state.

## Adversarial verification
Diff frozen RV64 traces before and after, construct values with nonzero upper 32 bits at every
new width boundary, and sabotage one mask. Any RV64 digest drift, leaked upper bits, or profile
mismatch accepted at runtime refutes. Inspect recorded coverage for every new width branch.
