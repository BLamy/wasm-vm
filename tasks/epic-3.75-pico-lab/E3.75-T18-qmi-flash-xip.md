## Goal
Execute Pico SDK code from emulated external flash through RP2350's QMI/XIP windows with the
address translation and cache-control behavior needed by the scoped firmware.

## Context
Pico 2 stores code in 4 MiB QSPI flash while RP2350 can expose translated runtime windows
beginning at `0x1000_0000`. This task models observable reads, instruction fetch, translation,
cache enable/flush, and bounds—not QSPI electrical timing or general flash programming.

## Deliverables
- A 4 MiB immutable-by-default flash backend populated by UF2.
- QMI/XIP runtime translation, documented cache/control registers, fetch/data reads, flush, and
  deterministic fault behavior for unsupported programming commands.
- Cross-window, cache, self-read, and paired ELF/UF2 execution tests.
- Browser live test and `make verify-E3.75-T18`.

## Acceptance criteria
- [ ] `make verify-E3.75-T18` executes the pinned UF2 from XIP to its checkpoint with native/WASM
  trace, UART, and state digest equality.
- [ ] Translation at the first/last byte, 4 KiB boundaries, disabled windows, and flash end
  matches the frozen datasheet-derived vectors.
- [ ] Cache enable/flush changes performance state only, never architectural bytes; reset restores
  the documented mapping.
- [ ] Unsupported erase/program sequences fail explicitly without mutating flash; the browser
  panel marks XIP `live`.

## Adversarial verification
Fetch across window and flash boundaries, change translation while executing, flush between
halfword fetches, and attempt writes through every alias. Compare cached/uncached traces and cold
runs. Any stale instruction, writable XIP shortcut, wraparound, or host-timing dependency refutes.
