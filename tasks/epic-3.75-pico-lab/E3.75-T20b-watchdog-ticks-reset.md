## Goal
Model the RP2350 watchdog's tick sources, countdown, scratch registers, reason bits, and
deterministic reset effects.

## Context
Pico SDK uses watchdog scratch/state during boot and reset flows. A watchdog expiry crosses many
device boundaries, so it needs its own exact reset contract rather than being hidden inside the
clock or timer implementation.

## Deliverables
- Watchdog load/control/tick/scratch/reason behavior attached to the deterministic event scheduler.
- A reset-propagation table and implementation for harts, SRAM, flash, clocks, and each landed
  device.
- Expiry, disable/rearm, scratch persistence, reset-reason, snapshot, and browser tests.
- `make verify-E3.75-T20b`.

## Acceptance criteria
- [ ] `make verify-E3.75-T20b` passes frozen watchdog/reset traces in native and wasm32 builds.
- [ ] Expiry at boundary ticks, rearm/disable, pause, scratch values, reason bits, and repeated
  resets match the documented RP2350 subset.
- [ ] Volatile state clears and retained state survives exactly according to the reset table;
  no pending event fires from the old generation.
- [ ] Browser reset/expiry produces the same digest and marks watchdog `live`.

## Adversarial verification
Write control on the expiry tick, reset during DMA/UART-shaped activity, snapshot immediately
before expiry, and repeat resets without reloading. Inspect every registered reset callback.
Any zombie event, incorrect retained byte, double reset, or native/WASM divergence refutes.
