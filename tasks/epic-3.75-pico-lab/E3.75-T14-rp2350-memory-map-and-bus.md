## Goal
Create an authoritative RP2350 machine map for ROM, XIP, 520 KiB SRAM, APB/AHB peripherals, SIO,
and private regions, with the chip's atomic alias and narrow-write behavior.

## Context
The current `virt` platform is page-oriented and 64-bit-addressed. RP2350 uses a 32-bit bus,
sub-page MMIO blocks, set/clear/XOR register aliases, restricted instruction-fetch regions, and
holes that must fault rather than behave like RAM.

## Deliverables
- An `rp2350` platform definition separate from `virt`, containing all in-scope regions and IRQs
  from one source of truth.
- Bus routing for byte/halfword/word accesses, APB narrow writes, atomic aliases, fetch
  permissions, and deterministic unmapped faults.
- Map-validation and datasheet-table tests plus `make verify-E3.75-T14`.

## Acceptance criteria
- [ ] `make verify-E3.75-T14` validates every region boundary against a checked-in extracted
  datasheet manifest and rejects overlaps, wraps, or accidental `virt` addresses.
- [ ] 520 KiB SRAM is contiguous at its documented base; ROM is read-only; peripheral regions
  cannot be fetched as code.
- [ ] Atomic SET/CLEAR/XOR aliases and narrow IO writes affect exactly the specified lane/bits.
- [ ] Unsupported and secure-only holes return typed deterministic faults, never zero-filled
  success.
- [ ] The browser runs an RP2350 map smoke fixture, reports the platform `live`, preserves the
  RV64 suite total, and has zero console errors.

## Adversarial verification
Probe first/last/outside bytes of every region, all access widths and alignments, alias addresses,
instruction fetches from MMIO, and 32-bit wraparound. Sabotage one manifest base and ensure the
gate fails. Any overlapping target, host panic, or permissive hole refutes.
