## Boundary

Add an opt-in diagnostic capture after the existing R3 physical-input trial
has failed at its unchanged deadline. Pause the owned VM, export its actual
in-memory guest RAM through the debugger, and bind the bytes to that
run. The production runtime, image, startup and input acceptance stay unchanged.
This captures a later guest state; it is not a responsiveness fix or a reusable
disk/snapshot pair. Disk overlays are not exported.

## Deterministic acceptance

`node tools/verify/omarchy-input-wait.mjs evidence/omarchy-profile/input-wait-r3`

- Preserve the 120-second independent nonce readback verdict and physical
  keyboard evidence before any diagnostic work. No nonce via serial.
- Pause immediately on failure and record request/ack timestamps. Export once
  while paused; bind the extracted region to the VM's actual RAM digest before
  and after export. Bound this separate diagnostic phase to 180 seconds and retain
  the owned-process cleanup watchdog. Never resume guest execution for capture.
- Record the actual served runtime and R3 identities, snapshot length/digest,
  original input result, pause state and cleanup. Record raw guest RAM, explicitly
  without current CPU registers or device sections; this is not a resume snapshot.
- Compare the exact saved compositor/renderer PID and start time, kernel wait,
  and saved user context with T03n where the captured context supports it.
  Identify current task membership from on-CPU state, and never call its stale
  switch/trap contexts current registers. Fail closed if interpretation is unsupported.
- Focused harness tests reject capture before the deadline, altered verdicts,
  ambiguous machine instances, truncated exports and watchdog extensions from
  repeated messages. No runtime build or unchanged regression wall is needed.

## Adversarial verification

A fresh critic checks the actual-source input deadlines and wire records,
predicts the capture's state before opening it, independently checks cited
snapshot bytes and identities, and performs one bounded corrupted-record
attack. Carry T03n HELD results forward for unchanged code/layout/evidence.
No claim about wait ownership, userspace symbols or a latency fix is accepted
without separate evidence.
