`LP_NUM_THREADS=0` setting on a fresh graphical session of an isolated copy of
the same verified SDR image. Do not change the emulator, packages, permissions,
GPU architecture, production artifacts, or input deadline. No Epic 6 work.

## Acceptance criteria

- Change only the two `LP_NUM_THREADS=1` values to `LP_NUM_THREADS=0` in
  `/etc/environment.d/60-omarchy-browser.conf` and
  `/home/omarchy/.config/uwsm/env`. Bind the original image, two changed bytes,
  resulting image/chunk manifest and unchanged inode metadata.
- Use a fresh real-emulator session. Bind kernel/core/image identities and
  the actual compositor PID's environment. A startup timeout is unproven,
  not a negative compatibility result. Preserve the 90-minute cold-start
  budget separately from input measurement.
- If startup succeeds, capture a paired RAM/disk snapshot and run the actual
  built browser's physical nonce/readback test with screenshots. Keep the
  existing 120-second deadline and use no serial writes of the nonce.
- Compare against the corrected, unchanged LP1 baseline r2 from T03f. A
  failed input run establishes only that the exact LP0 configuration did
  not fix responsiveness; do not invent a renderer label or mechanism.
  A crash requires a PID-bound terminal record. Missing evidence is unproven.
- A successful or materially improved LP0 result is provisional: before
  attributing improvement or publishing, repeat matched clean LP1/LP0 arms
  with startup DEBUG logging identically enabled, capture each measured
  compositor's strict GL labels, then identically disable logging before
  timing physical input. An auxiliary EGL client cannot identify the
  compositor's active renderer.
- A fresh critic audits the scoped measurement before this prerequisite
  can become verified. A verified negative diagnostic is not a desktop fix.
