## Goal

Remove whole-block FP exclusion as an avoidable obstacle to the Omarchy software
renderer while preserving every FP operation on the existing interpreter.

## Boundary

One deterministic decoded-block partition policy: split integer and FP regions
at their boundaries. Architectural branch/CSR/page/cap termination remains
unchanged. Do not translate FP, add an FP register ABI, change arithmetic or
clock semantics, add GPU acceleration, or alter JIT cache/admission policy.

## Acceptance criteria

- Integer prefixes and continuations surrounding FP operations can actually
  execute through the existing JIT; FP regions remain untranslatable.
- Interpreter-versus-JIT final integer/FP state, fcsr, memory, traps and retired
  instruction counts remain equal for mixed F/D/C programs, including FP-off,
  faulting memory, NaN-boxing, rounding/fflags, and self-modifying/page-edge cases.
- The partition is deterministic and preserves the existing interrupt-latency
  bound; repeated native/wasm runs retain their deterministic verdicts.
- An actual paired Omarchy browser restore exercises the candidate. Record
  elapsed physical input, successful presentations, interpreter/JIT counters,
  and screenshots; do not infer desktop responsiveness from a synthetic loop.
  If it does not materially help the recorded renderer bottleneck, do not
  promote this as the desktop fix.

## Verification command

`cargo test -p wasm-vm-jit-runtime --test mixed_fp_regions`

Also run the affected core predecode/interrupt/SMC tests, FP compliance verdict
comparison, the wasm build/browser path, and the high-risk final submission at
the frozen candidate. Host rr is waived by repository policy. A fresh verifier
owns the verdict; no GitHub Actions and no automatic merge.

## Adversarial verification

Attack the integer-to-FP and FP-to-integer handoff separately. Reject duplicate
or skipped instructions, stale register writeback, a changed FP-off/fault PC,
lost fflags, new compiled FP code, or a changed page/SMC authority boundary.
Check entry into the middle of a region, alternating FP/integer instructions,
compressed FP loads/stores, and repeated executions at tiny cache sizes.
Require real browser evidence for any responsiveness claim and preserve held
unrelated snapshot/integrity findings incrementally.
