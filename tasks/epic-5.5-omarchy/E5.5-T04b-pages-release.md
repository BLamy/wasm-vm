## Boundary

Stage and deploy the exact verified browser build and immutable Omarchy assets
to the existing `wasm-vm` Cloudflare Pages project at
<https://wasm-vm.pages.dev>. No GitHub Actions, new paid service, account change,
or Epic 6 work. Merge only with an explicit current user merge request.

## Acceptance criteria

- Release staging verifies kernel and rootfs/chunk identities before upload;
  the build, boot manifest and stored bytes refer to the same verified release.
- The entire staged asset set is under the existing Pages account's file count
  and per-file size limits. The clean rootfs may be published as 256 KiB hashed
  chunks on Pages; never upload a private source disk or previously booted copy.
- Deployment is to the existing production project, not a substitute host.
- A fresh production Chromium context reaches the actual Omarchy desktop and
  confirms terminal keyboard input without an integrity error. Record URL,
  deployment identifier, exact artifact hashes, screenshot and guest result.
- Stop before Epic 6. Do not relabel an unmet historical performance criterion
  as verified on the strength of this deployment.

## Verification command

`bash tools/deploy-cloudflare.sh`

Record the exact stage-validation and production-browser acceptance commands
when implemented; a successful upload alone is not desktop acceptance.

## Adversarial verification

Check stale manifests, mismatched bytes, accidental publication of personal
data, old writable-state imports, and incomplete uploads. A missing artifact or
exceeded platform limit must abort before production mutation. Keep unrelated
worktree changes out of the staged source commit. Verify the real public URL,
not just a local proof or preview deployment.

## Verification log

### 2026-09-09 — planning — existing-account publication option

Cloudflare documents 20,000 files and 25 MiB per file for a free Pages site:
<https://developers.cloudflare.com/pages/platform/limits/>. Its static requests
are free and unlimited:
<https://developers.cloudflare.com/pages/functions/pricing/#static-asset-requests>.
The installed Wrangler4.129 uploader enforces those limits and batches asset
uploads. A 4 GiB image split into 256 KiB chunks has at most 16,384 chunk files,
leaving room for the approximately 290 web assets without requiring new R2
credentials. This is a staging plan, not evidence of an upload or successful
production boot.
