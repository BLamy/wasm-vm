## Goal

Remove the native Omarchy boot failure where a supported scalar load crossing
adjacent virtual pages is rejected solely because their physical pages are not
adjacent. Preserve preflight fault behavior and device silence for stores.

## Boundary

The shared scalar misaligned-memory path in `crates/core/src/hart/mod.rs`,
its deterministic tests, and a live browser guest regression. Do not alter LR/SC/AMO alignment requirements or bypass
page permissions/PMP. A noncontiguous store must not report one contiguous
physical range to the browser JIT continuation path.

## Acceptance criteria

- Two adjacent Sv39 virtual pages mapped to separated physical RAM pages support
  the existing scalar load/store widths and sign/zero extension across the edge.
  Byte results match a separately constructed expected value in both interpreter
  execution and JIT host-import paths.
- All touched page translations, RAM membership and PMP permissions are checked
  before the first byte of a store is written. An inaccessible second page leaves
  both data pages unchanged and reports the appropriate page/access fault.
  The reported virtual address identifies the failing fragment (the second page
  boundary for a second-fragment fault), per the privileged ISA fault-portion rule.
- Device-adjacent or non-RAM paths do not invoke device operations. Faulting
  stores preserve reservations. Contiguous/aligned behavior is unchanged.
- A split physical store returns no contiguous-RAM continuation hint, ensuring
  the browser JIT observes the complete physical write log before continuing.
- Record a guest state digest for the regression and a confirming native Omarchy
  boot of the accepted image past the previous systemd failure. This does not
  establish first-run configuration, a browser desktop or performance budgets.
- The built demo runs the new Sv39 guest regression with the complete 127-test
  browser suite, zero failures/errors, and a live roadmap capability.

## Verification command

`cargo test -p wasm-vm-core --test misaligned_virtual_pages`

## Adversarial verification

Use physical pages in both ascending and descending order, all width-specific
crossing offsets, a missing/read-only second page, PMP denial, a device-backed
second mapping, and a shared physical-page alias. Inspect the first-page bytes
after each failed store. Exercise the exact `jit_store_with_ram_phys` result;
do not assume checking the first physical page also covers the second.
