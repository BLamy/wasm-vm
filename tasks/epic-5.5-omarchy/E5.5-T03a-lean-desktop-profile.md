## Goal

Turn the verified package image into a ready-to-use, deliberately lean Omarchy
desktop profile. Preserve package-owned Hyprland, Quickshell and Foot; initialize
only the selected demo capabilities and retain no personal or legacy VM state.

## Boundary

The image builder and reviewed demo overlay. Precompute package caches on the
builder, remove startup waits for nonexistent devices, and select an explicit
first-login profile for the applications actually present. Do not fabricate
upstream full-install completion markers or silently grant administrative access.
Browser UI/default manifest publication is the following integration slice.

## Acceptance criteria

- Fresh image assembly is checked, sanitized and content-addressed using the
  E5.5-T01a tools. Exact input, image, and chunk digests are recorded.
- Required hardware database and package caches are generated during the image
  build; boot does not redo them solely because assembly left missing caches.
- No enabled demo service repeatedly tries to execute an absent binary; the
  profile does not wait for a serial device the emulator does not expose.
- A fresh guest session reaches Hyprland with the Omarchy shell and a mapped,
  keyboard-usable Foot window. The generic demo account remains non-root with
  locked passwords. Source personal data and old user state remain excluded.
- The demo's provisioning marker, if needed, is distinct from upstream full
  Omarchy setup markers and is written only after its own steps succeed.
- Record an actual emulator boot or browser capture plus deterministic tests;
  QEMU is only a fast pre-check, not proof that wasm-vm works.

## Verification command

`python3 -m unittest discover -s tools/image -p 'test_*.py'`

Run the recorded guest-session acceptance at the final image digest in addition
to this deterministic tool gate. This slice does not claim a performance budget
or a successful production deployment.

## Adversarial verification

Inspect before/after accounts and file provenance. Reject any build that ignores
a failed cache command, marks incomplete setup successful, mutates the accepted
source image, or enables absent executables. Inspect a fresh session with no
previous home, runtime, display cache or writable disk overlay.
