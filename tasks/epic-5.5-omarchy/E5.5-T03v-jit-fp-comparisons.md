invalid-operation flag, through the existing FPR/FS handoff. Keep rounded
arithmetic and double-precision comparisons outside this slice. This is one
comparison/state boundary, not a blanket FP implementation.

## Deterministic acceptance

- Real generated native, private browser and shared browser modules agree with
  the interpreter and independent bit-pattern goldens for FEQ.S/FLT.S/FLE.S:
  both signed zeros, infinities, subnormals, opposite signs, ordinary positive
  and negative ordering, quiet/signaling NaNs and malformed single NaN boxes.
  Integer x0 remains zero; all source FPR bits remain unchanged.
- Preserve fflags as sticky state: FEQ's signaling-NaN invalid flag differs
  from FLT/FLE's any-NaN invalid behavior. Never erase an existing flag or alter
  frm. Successful comparison follows the interpreter's FS dirty transition,
  even if it writes x0. Reserved frm values do not trap a non-rounding compare.
- FS-Off returns the exact raw instruction and virtual fault PC after any
  completed prefix. Flag/FPR handoff stays coherent across interpreter changes,
  same-/cross-module successors, budget exits, subsequent memory faults and
  browser memory growth. Newly accrued flags survive the existing precise exit.
- Record the high-risk local submission and unchanged platform limitations,
  full live browser ISA plus a compiled comparison guest, exact source/artifact
  and guest-state hashes, and one final pristine clone. Update web/dist and the
  live capability through Cloudflare; no Actions or merges.
- Repeat the actual Omarchy physical-keyboard nonce test at the unchanged
  120-second deadline and inspect the real application screenshot. Keep T03q
  pending until independent readback and visible response both succeed.
