## Boundary

Inspect the existing R3 RAM checkpoint offline. T03h records a sleeping
compositor and an executing renderer, but cannot identify the saved wait or
its caller. The checkpoint includes their kernel stacks and saved userspace
registers. Decode those bytes using the exact matching kernel and its build
layout; do not start a guest, modify runtime/image defaults, or repeat the
failed physical-input experiments.

This is a checkpoint observation, earlier than T03m's physical-input attempt.
It cannot establish that the same wait persisted through the later failure,
that a runnable task was executing at the checkpoint, or that input works.
T03d remains a planning container until a measured cause supports a remedy.

## Deterministic acceptance

- Bind the exact compressed snapshot, kernel Image, System.map and kernel
  layout provenance. Validate the actual saved address-translation mode and
  kernel code bytes before interpreting task fields.
- Traverse the real task/thread lists with reciprocal-link, identity and
  traversal bounds. Report PID/TGID, name and saved state; a RAM string search
  alone is not a task identity proof.
- Recover bounded kernel frame chains and the saved trap registers for the
  compositor leader and its renderer. Cite physical byte addresses, raw
  values and enclosing kernel symbol ranges. Stop on an invalid chain; do
  not guess through it. Distinguish saved user context from live execution.
- Identify the concrete checkpoint wait where supported, and state the
  remaining probe needed to connect it to the observed input failure.
- Focused deterministic tests reject corrupted kernel/layout identity,
  invalid page-table entries, broken task links and invalid frame chains.
  No native/WASM rebuild or browser run is required for this offline tool.
