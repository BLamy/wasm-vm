## Boundary

T03l removes hidden IDE/agent traffic. Its actual page emits desktop-ready at
211.898 seconds, but the recorder then invokes `hyprctl clients` (and would
invoke `activewindow`) before sending any key. That diagnostic command does
not finish within the remaining71 seconds. A real user can type as soon as
the overlay clears and does not first issue those two commands.

This makes the result startup-qualification-negative, not measured keyboard
latency. Test that distinction with one direct-user-path recording, not a
runtime tuning experiment or a claim that the existing product is fixed.
The substantive success evidence remains physical guest input, independently
verified effects, and actual newly rendered GUI pixels.

## Scope

Change only the browser proof harness/tests. For the bounded input trial,
omit the recorder-only `clients`/`activewindow` pre-input RPCs. Preserve them
where separately required for image capture/renderer attestation. Do not
change the app's real layers-plus-pixels readiness check, UI overlay, guest,
renderer, clocks, JIT policy, agent lifecycle or persistence.

Begin after the actual desktop-ready event, inspect/capture the visible desktop,
click its real canvas and prove DOM focus. Keep the300-second navigation-to-
input-start,60-second typing, Enter-anchored120-second readback,20-second final
capture and bounded owned-browser cleanup limits. No serial injection of the
nonce, readiness synthesis, injected guest result, fake pixels or deadline reset.
