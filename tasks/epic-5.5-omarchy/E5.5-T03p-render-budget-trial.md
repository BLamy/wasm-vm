## Boundary

One local tooling-only trial of the existing display-mode API on the exact R3
snapshot and unchanged production WASM/image. Request 640×400 once after the
real desktop becomes available. This quarter-area mode tests the rendering-work
hypothesis exposed by T03o; no renderer, timing, JIT or architecture change.
The browser canvas is not a substitute for an actual smaller guest resource.

## Deterministic acceptance

`node tools/verify/omarchy-render-budget.mjs evidence/omarchy-profile/render-budget-r1`

- Bind the existing R3 artifacts, actual served sources and frozen helpers.
- Record the original guest scanout, one actual setDisplay(640,400) RPC and its
  acknowledgement. Require a new guest frame and bound 640-pixel-wide scanout
  before calling the mode adopted; account explicitly for stride/height padding.
- Modeset observation uses the original absolute 300-second startup deadline.
  A modeset timeout remains input-not-tested, never a negative latency result.
- Once the mode is adopted, use unchanged physical typing, the independent
  filename/nonce, 120-second readback, fresh presentation and actual screenshot.
  No nonce bytes via serial, no fabricated frame or readiness, no timeout tuning.
- Record an honest bounded outcome: mode-not-observed, physical-input-failed,
  or physical-input-and-presentation-passed. Only the final outcome can support
  product promotion in T03q. Tooling acceptance does not mean desktop acceptance.
- Preserve owned-process cleanup and record no browser errors. Relevant helper
  tests reject an acknowledged mode without actual guest scanout/frame evidence,
  expired deadlines and wrong input bytes. No production build/deploy is claimed.

actual recording, audits the single modeset RPC, original input deadline and

receipt attack. Carry unchanged T03o runtime, R3 identity and input-harness
