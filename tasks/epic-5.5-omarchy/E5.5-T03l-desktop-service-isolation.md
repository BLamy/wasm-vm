## Boundary

The user requested a fullscreen Omarchy desktop, with the IDE only for CLI
guests. T03k's actual wire records show desktop mode nevertheless runs the
hidden IDE's `ls -la '/root'` at readiness. That command holds the serialized
console bridge for30 host seconds before the desktop layer query can start.
Both runs also send hundreds of binary agent messages; their exact producer
must be identified from code before claiming that they are unnecessary.

Prevent CLI-only guest-service initialization/work for the actual Omarchy
desktop session, preserving normal CLI guest behavior and the real desktop's
keyboard, pointer, resize, presentation and relevant media bridges. Do not
simply hide more DOM or disable all controller input. Identify the current
session from authoritative app state, not an untrusted visual class alone.
Do not change the renderer, image, clocks, JIT policy or input deadlines.

This is removal of demonstrated unwanted work, not a prior claim that it is
the entire cause of the input stall. No implementation starts before T03k's
fresh verdict closes the active lane.

## Deterministic acceptance

`node --test web/tests/omarchy-desktop-services.test.mjs`

- The real service lifecycle starts no CLI Explorer/file-transfer guest work
  for an Omarchy desktop session, including delayed guest-ready events.
- Desktop keyboard/pointer/resize/presentation entry points remain enabled.
- The same lifecycle for Alpine/BusyBox/container-capable CLI sessions still
  initializes its expected IDE/file-transfer services exactly once per session.
- Guest/session changes dispose or fence stale work without suppressing the
  subsequent eligible CLI session. Cover only transitions supported by the app.

Use source-driven integration tests around the actual lifecycle, not a standalone
predicate never called by the app. Run affected browser tests and the built ISA
smoke. Record one bounded actual R3 Omarchy desktop run with unchanged300-second
startup and120-second physical nonce readback limits; inspect actual screenshots
and wire traffic for the removed calls. A screenshot or fewer background calls
alone cannot establish responsive input. Preserve a failed input observation
and keep the broader T03d usability goal unresolved if necessary.

## Adversarial verification

before the final run. Attack one stale/delayed callback or supported guest
transition; it must not restart the hidden IDE in an Omarchy session. Check
ordinary CLI startup still works. Verify actual runtime wiring and screenshots,
not only the new fixture. No unrelated native gauntlet for unchanged Rust.
