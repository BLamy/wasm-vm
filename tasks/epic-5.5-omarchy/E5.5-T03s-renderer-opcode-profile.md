## Boundary

Measure the existing R3 desktop snapshot with the existing native retirement
histogram. This tool-only slice chooses a renderer execution remedy after T03r
showed that a live resize produces a black display and failed physical input.
The older R2 profile is not silently treated as the current target's result.

## Deterministic acceptance

`node tools/verify/omarchy-renderer-opcodes.mjs evidence/omarchy-profile/renderer-opcodes-r1`

- Pin and validate the actual R3 snapshot, kernel, image and chunk manifest;
  validate every paired delta record and apply it only to a new private image.
- Build and hash the native CLI from the frozen task head. Run a fixed100-million
  attempted-instruction budget, no keyboard/serial input, ICount64, with the existing raw-opcode
  histogram and retirement digest. Preserve full commands, stdout/stderr, exit,
  final state digest, opcode counts and PC-region counts.
- Explicitly document the local native diagnostic adaptation: the CLI currently
  expects zero coherence IDs on restore. After independently checking the R3
  core/base/generation binding, zero only the64-byte core/base fields in a private
  snapshot copy, and verify every remaining byte is unchanged. Never overwrite
  or publish that copy. This is not restore-coherence or performance acceptance.
- Independently recount FP categories from the raw-opcode histogram and identify
  hot PC regions. Report every histogram truncation. Apply the measured reopening
  condition in `docs/jit-fp-policy.md`; do not claim a JIT gain or desktop response.
- Bound the owned process to five minutes and preserve failures; cleanup leaves
  no native emulator running. Keep source artifacts unchanged. Relevant tool
  tests attack wrong identity, malformed/duplicate delta records and count drift.

## Adversarial verification

A fresh critic records predictions before inspecting the actual measurement,
recounts raw categories independently, checks source/private-byte differences,
and attacks one altered region or histogram total. The allowed identity-field
adaptation must be explicit in the receipt and cannot support a restore claim.
Actual responsiveness remains the unchanged browser nonce/presentation gate.
