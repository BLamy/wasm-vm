## Boundary

Measure the existing R3 desktop snapshot with the existing native retirement
histogram. This tool-only slice chooses a renderer execution remedy after T03r
showed that a live resize produces a black display and failed physical input.
The older R2 profile is not silently treated as the current target's result.

## Deterministic acceptance

`node tools/verify/omarchy-renderer-opcodes.mjs evidence/omarchy-profile/renderer-opcodes-r1`

- Pin and validate the actual R3 snapshot, kernel, image and chunk manifest;
  validate every paired delta record and apply it only to a new private image.
- Build and hash the native CLI from the frozen task head. Run a fixed100-million
  attempted-instruction budget, no keyboard/serial input, ICount64, with the existing raw-opcode
  histogram and retirement digest. Preserve full commands, stdout/stderr, exit,
  final state digest, opcode counts and PC-region counts.
- Explicitly document the local native diagnostic adaptation: the CLI currently
  expects zero coherence IDs on restore. After independently checking the R3
  core/base/generation binding, zero only the64-byte core/base fields in a private
  snapshot copy, and verify every remaining byte is unchanged. Never overwrite
  or publish that copy. This is not restore-coherence or performance acceptance.
- Independently recount FP categories from the raw-opcode histogram and identify
  hot PC regions. Report every histogram truncation. Apply the measured reopening
  condition in `docs/jit-fp-policy.md`; do not claim a JIT gain or desktop response.
- Bound the owned process to five minutes and preserve failures; cleanup leaves
  no native emulator running. Keep source artifacts unchanged. Relevant tool
  tests attack wrong identity, malformed/duplicate delta records and count drift.

## Adversarial verification

A fresh critic records predictions before inspecting the actual measurement,
recounts raw categories independently, checks source/private-byte differences,
and attacks one altered region or histogram total. The allowed identity-field
adaptation must be explicit in the receipt and cannot support a restore claim.
Actual responsiveness remains the unchanged browser nonce/presentation gate.

### 2026-09-15 — verifier — predictions before measurement

These predictions were written before any T03s actual measurement existed. The
critic has read the task, activation diff and existing `FpShareSink` path; results
below remain pending until the frozen worker evidence is submitted.

- P1 identity and isolation: the source R3 snapshot, kernel, base image, manifest
  and paired delta will match independently recomputed pinned hashes. The private
  snapshot will differ from the decompressed source only within the exact 64-byte
  core/base ID range, whose original values must match the independently checked
  R3 binding. Its generation and every byte outside that range will be unchanged.
  Delta indices must be unique, in range and complete; the private image must equal
  source bytes plus precisely those validated overlays. Source hashes after the
  run must remain equal to their hashes before the run.
- P2 bounded, uninjected execution: the frozen CLI build/hash, full argument and
  environment receipt will identify the existing retirement-record histogram
  path, the 100,000,000-attempt budget and ICount divisor 64. No keyboard, serial
  input or workload injection may enter the diagnostic. Actual retired count must
  be positive and no larger than the attempt budget. The existing CLI's budget
  completion exit 102 is expected only alongside `MaxInstrs`; every unexpected
  exit or owned process exceeding five minutes must remain a failed run in the
  receipt. Final process inspection must find no owned native emulator.
- P3 independent counters: the sum of the complete opcode7 histogram must equal
  `total_retired`, which must equal the record-hash retirement count and evidence
  retirement count. Summing OP-FP and the four FMA opcode counts must reproduce
  `fp_compute`; the OP-FP funct7 sum and FMA breakdown must agree with their opcode
  totals. Region counts plus any reported dropped counts must conserve retirement
  totals, and the FP compute sum must be reconciled with any region truncation.
  A changed count in a copied histogram must be rejected. Only recoverable
  categories will be called independently recounted: low-seven-bit opcode totals
  cannot alone reconstruct compressed FP load/store funct3 bits.
- P4 decision and limits: the measured FP-compute fraction and hot 64-byte PC
  regions will support exactly the policy reopening condition they demonstrate.
  Top-32 pair output and every capacity truncation must be disclosed. A material
  FP count cannot itself prove that a JIT remedy is faster, that a native-adapted
  restore is coherent, or that physical browser input is responsive.
- COVERAGE prediction: all new behavior must appear in the recorded diagnostic or
  the scoped tool tests, with identity mismatch, malformed/duplicate delta and
  count-drift cases explicitly exercised. Build/receipt/declarative-only hunks may
  be waived with a specific reason. No runtime or browser changes are in scope.
