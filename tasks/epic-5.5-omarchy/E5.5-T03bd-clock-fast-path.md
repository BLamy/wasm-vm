## Boundary

Optimize only `Machine::advance_clock_by`: accumulate a span with checked u64
addition, skip division when it produces zero or one exact tick, use native u64
division for other nonoverflowing spans, and retain the existing u128 oracle
when addition overflows. Preserve mtime wrapping, fractional phase, divider-zero
clamping, wall-clock/no-CLINT no-ops, timer interrupt boundaries, and resume bytes.
Keep the current JIT, guest artifacts, desktop geometry and input deadlines.

The verified worker-cost recording contains 699,612 us of `__udivti3` self time
(2.3301%); 523,565 us have `Machine::run` as their parent. The clock arithmetic
body is unchanged since that recording. This justifies a bounded investigation,
not a prediction of present desktop speed or responsiveness.

## Deterministic acceptance

  arbitrary dividers, phases, retirement spans, overflow and wrapping. Exercise

  native and wasm; retain a canonical guest trace and state digest.
- Run formatting, affected strict clippy, core tests, CLINT/SBI timer, clock,

- Run the built demo suite with zero errors, update the existing timer capability
  evidence, commit dist, publish through Cloudflare, and perform final exact-head
  cold-clone checks. Run the local prescribed gauntlet once at the frozen head;
  explain any pre-existing failure rather than masking it.

## Adversarial verification

A fresh critic predicts tick and phase values before inspecting evidence;
attacks u64 addition overflow, the largest divider, mtime wrap, a nonzero restored
phase, wall mode and missing CLINT. Check the actual compiled accounting path as
well as interpreted rdtime. Independently recount paired timing/state receipts,
invent one bounded attack, sabotage a new assertion once, and audit every changed
runtime branch. Preserve old desktop failures; T03q still needs both independent
physical nonce and visible application response at its original deadline.
