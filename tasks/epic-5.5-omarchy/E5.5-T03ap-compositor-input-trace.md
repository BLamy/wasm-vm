## Boundary

Record where the existing physical keyboard sequence reaches Linux and the
compositor on the exact AO runtime and AJ R2 prepared desktop. Host virtio
acknowledgments and an empty device queue do not establish userspace consumption.
AO still had no nonce after 120 seconds despite one new presentation frame.
Do not infer that another arithmetic optimization will fix the input path.

Use one bounded diagnostic harness and, if needed, a small temporary guest
syscall observer to inspect actual input-device reads. Bind compositor PID,
input fd/device identity, syscall return values and raw event bytes. Preserve
observed SYN_DROPPED, partial reads, no-read intervals and observer failures.
Keep the runtime, numerical backends, admission/cache/clock configuration,
prepared pair, presentation and original input deadline unchanged. Tracing is
diagnostic and can perturb scheduling; it cannot itself establish an untraced
responsiveness improvement. No guest service replacement, focus injection,
nonce writer, resolution change or GPU expansion belongs in this task.

## Deterministic acceptance

`make verify-E5_5-T03ap`

- Prove any syscall observer against a deterministic local Linux fixture with
  exact independent input bytes, short reads, unsuccessful reads and clean
  detach; build the same source for riscv64. The local fixture is a pre-check,
  not the authoritative guest result.
- Freeze the diagnostic harness and observer digest. Restore the exact AO/AJ
  state in one owned browser. Record process/input-fd identity and the real
  trusted key sequence, retain the original Enter+120s readback deadline, and
  take real before/after images. Bound preparation, sampling and cleanup with
  host deadlines and preserve all failures. Do not silently attach to the wrong
  process or device. Diagnostic guest files remain separate from the nonce.
- Associate recorded evdev bytes with their actual consuming process and fd;
  compare keys/sync/drop events to the physical sequence. If no such read is
  observed, say so and retain process/thread state and the observer's proof of
  attachment. A second reader's queue is not the compositor's queue.
- Record the narrowest supported next action. Any remedy requires a subsequent
  uninstrumented physical nonce and visible returned-prompt trial before T03q.
  Carry AO correctness and artifact proofs unchanged; no unrelated regression
  gauntlet or deployment is required for this diagnostic-only tooling boundary.

## Adversarial verification

A fresh critic predicts attachment, input identity and byte-decoding results
before inspecting the run. Attack one bounded decoder/identity case, audit the
real trace against the physical sequence and inspect actual images. Separate
host delivery, kernel delivery and compositor consumption. Check observer
effects and cleanup; never promote a missing observation to evidence of a
specific deadlock or queue overflow.
