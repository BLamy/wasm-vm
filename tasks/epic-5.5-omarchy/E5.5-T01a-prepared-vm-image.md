## Goal

Turn the user's prepared Omarchy RISC-V VM into a separate, inspectable ext4
release candidate. Preserve the original live VM and remove personal state from
the candidate. This is the user's requested image-preparation priority, not an
Epic 6 task and not a claim that Omarchy already runs in the browser.

## Boundary

Own the consistent private source capture, copy-only preparation tools, clean
filesystem construction, package/image identities and local image checks.
Do not publish an unsanitized source image, change the live VM's accounts, carry
unallocated source disk blocks into the release, or bypass artifact integrity.
Browser/kernel integration and production publication follow this boundary.
Use the prepared VM rather than restarting the alternative checkout's proposed
base-from-scratch bootstrap. Do not claim bit-reproducible upstream provisioning.

## Acceptance criteria

- Capture is bound to the exact intended QMP disk, has no backing chain or
  concurrent block job, and restores the VM's prior run state even after a
  failed clone. Record consistency level and hashes of the immutable copy.
- A fresh filesystem contains the installed Omarchy/Hyprland/Quickshell software
  and pacman package database; it does not contain personal homes, bootstrap
  users, private host keys, tailnet identity, logs/history, caches or old free
  disk blocks. New demo account and machine identity policy are explicit.
- Preparation refuses unsafe targets and symlink escapes before mutation;
  deterministic tests cover these guards and replay/idempotence.
- Offline filesystem checks pass; exact size, image hash, package versions and
  content-addressed chunk identity are recorded. A second chunk verification
  reconstructs the exact image identity.
- Fresh Daybreak review interrogates the source/copy and public-state boundary.
  Anything not proven is retained as a release blocker, not called verified.

## Verification command

`python3 tools/image/verify-omarchy-image.py --image <candidate> --manifest <chunks/manifest.json>`

## Adversarial verification

Predict then test: wrong QMP disk, already-paused VM, clone failure, source
backing file, running block job; path traversal and symlinks into a host sentinel;
personal account/password/SSH/machine-id fixtures; repeated preparation; a
tampered chunk. Confirm the output is freshly constructed rather than copied
over a formerly personal ext4. Guest boot is a separate acceptance boundary,
not established by package names or a QEMU screenshot.
