## Goal
The default demo restores, in ~1 second, an Alpine host with **Node.js already installed** — so the
VM is instantly ready to run `node` programs with no boot and no `apk` wait. This is the payoff of the
epic-3.6 snapshot-restore work (busybox restore already ships at ~0.68 s; the browser Alpine restore is
the immediate prerequisite): freeze a *batteries-included* image and make restoring it the default.

## Context
Builds directly on the browser Alpine snapshot-restore (the RAM-snapshot + ~1 MB disk-overlay-delta
seeded over the 130 MB chunked base, generation-locked per E3-T12d). Adding Node is a small delta on that
pipeline: `apk add` Node into the Alpine image, reach a ready shell with `node` on PATH, then snapshot at
THAT point instead of a bare shell. The JIT (E4-T29, now integrated) is what makes the Node *workload*
usable — V8 emitting machine code at runtime also exercises FENCE.I coherence (E4-T16), tying into the
E4-T28 "interactive fast Node.js" capstone. Snapshotting after Node is ready removes Node's startup cost
from the demo entirely; only the actual program execution runs live (JIT-accelerated).

## Deliverables
- Alpine build image with `nodejs` (+ `npm`) installed via `apk` (pinned versions recorded); confirm the
  Alpine 3.20 riscv64 repo actually has `nodejs` — if not, document the fallback (build/vendor Node, or a
  different base). This is the first thing to verify.
- The build-snapshot pipeline (E3.6 Alpine restore) run against the Node image, snapshotting at a
  post-login shell where `node --version` succeeds; ship the RAM snapshot + overlay delta as the default
  boot artifact.
- Autoboot default switched to the Node-Alpine snapshot (extend the `?guest=` selector: e.g.
  `?guest=busybox` / `?guest=alpine` / default = node-alpine). Cold-boot fallback preserved.
- A visible "run Node" affordance in the demo (or a documented one-liner) so a user can execute a program.

## Acceptance criteria
- [ ] Default demo restores to a ready shell in ~seconds (sub-second RAM restore) with `node` on PATH —
      Playwright-verified on the deployed site: `restoredFromBootSnapshot()===true` AND `node --version`
      returns a version.
- [ ] A real Node program runs in the VM and produces correct output — Playwright-verified: e.g.
      `node -e 'console.log(6*7)'` → `42`, and a multi-line script (fs read/write, a small compute) runs.
- [ ] A `node` HTTP server started in-guest serves a request (guest-local or via the slirp stack) —
      or, if networking is out of scope here, a scripted `node` workload runs to completion with a
      recorded wall-time (JIT on vs off, ties to E4-T28).
- [ ] Coherence guard holds: a stale/foreign snapshot or mismatched overlay generation falls back to a
      clean cold boot, never a broken guest.
- [ ] Snapshot artifact size + restore time recorded in `evidence/epic-3.6/`; no fabricated numbers.

## Adversarial verification
Confirm it is a REAL Node, not a frozen illusion: (1) run a program that computes a non-trivial result at
runtime (not a canned string) and check the output; (2) `node -e` with input that varies per run (read
argv / Date-independent math) to prove live execution; (3) restore, then WRITE a file with node and read
it back — proves the restored fs is live and coherent; (4) measure `node` startup-to-first-output on the
restored host and compare to a cold `apk add nodejs && node` path — the snapshot must eliminate the boot +
install cost; (5) run under JIT and confirm no FENCE.I/i-cache faults from V8's own codegen.

### 2026-08-29 — worker evidence — local restored Node browser A/B

On the latest-main-derived head `37265f5`, served locally with `bash tools/serve-dev.sh 8130`, a
fresh headless Google Chrome `152.0.7977.65` session restored `node-alpine` and reached the ready
shell in `2.196s` (`jit=0`) and `2.083s` (`jit=1`). The identical runtime workload computed
`1..1000`, wrote the sum to `/tmp/node-local.txt`, read it back with Node's `fs`, and emitted the
unique marker `ADV_500500` with exit 0 in both arms. Raw evidence:
`evidence/epic-3.6/node-local-browser-ab-2026-08-29.json`.

The interpreter arm took `20,067.175ms`; the JIT arm took `20,813.240ms` (`1.03718x`, 3.718%
slower), while the JIT reported `hasExecutor:true`, `executedBlocks:4,903,315`, and
`retiredViaJit:24,518,003`. This fresh local run strengthens AC2's live-execution proof and
demonstrates that the current browser JIT path preserves output, but it does not claim a speedup;
the measured regression remains E4-T34 work. The only browser error was the allowed favicon 404.
