## Goal
Make the Docker tab's **Pull** button do the real thing when a network provider is configured: type a
ref, watch the in-guest `wvpull` fetch + digest-verify + unpack with honest progress, then the image
appears in the Images catalog and is immediately runnable — no baked bytes, no fake spinner.

## Context
E3.5-T05f6 ships Pull as an HONEST-gated affordance: with no provider it shows the baked set and says
live pull needs a provider. This task lights up the live path on top of E3.6-T02: the UI drives
`wvmDemo.stream('wvpull <ref>', onLine)` (the RPC/stream bridge from E3.5-T05e), parses wvpull's
progress lines (blob k/N, bytes, verify OK), and refreshes the catalog from
`/opt/containers/index.json` on success. Preserve the honesty guarantees: progress reflects the guest's
REAL wvpull output, errors are the guest's real typed errors, and a pulled image is only listed after
the guest confirms the bundle exists.

## Deliverables
- A Pull dialog: ref input + arch (riscv64), provider-status indicator (offline → the honest baked-set
  message; provider up → live pull enabled).
- Live progress from real `wvpull` output (per-blob download + verify), a final digest + size summary,
  and catalog refresh so the new image shows in Images with Run/Inspect.
- Real error surfacing: connect-refused / no-riscv64 / digest-mismatch → the guest's typed error in the
  dialog, no partial "pulled" row.
- The pulled image runs via the existing Run→Containers→Logs→Exec lifecycle (no special-casing vs baked
  images once unpacked).

## Acceptance criteria
- [ ] Gated Playwright (provider up, local Alpine assets): open Docker tab → Pull `busybox` → progress
      lines stream from real wvpull → on success the image appears in Images → Run it → Containers shows
      it running → Logs shows the guest-computed marker. Every value is guest-sourced (echo-proof); the
      image was fetched at runtime, not baked.
- [ ] Provider offline: Pull shows the honest "needs a provider" state and the baked set; no fake
      progress, no phantom image row.
- [ ] A failed pull (bad ref / mid-pull drop) shows the guest's real error and leaves the catalog
      unchanged (no half-listed image).
- [ ] Static-source honesty asserts hold (no canned progress/transcript/digest in docker.js; markers
      guest-evaluated).

## Adversarial verification
The UI must not list an image the guest didn't actually unpack (catalog derives from the guest, not an
optimistic client update). Progress cannot be fabricated when the stream stalls (a stalled pull shows
stalled, not fake advancing bytes). A ref that resolves to an error page is rejected (the guest's
HTTP-code/verify check, surfaced honestly). Re-render mid-pull does not double-count progress or drop
the final result.
