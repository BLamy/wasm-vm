## Goal
Prove `wvpull` (E3.6-T01) reaches a REAL registry over the in-browser guest's network — i.e. a running
browser VM booted with a network provider pulls `busybox:riscv64` from Docker Hub, digest-verifies it,
and unpacks a runnable bundle, with ZERO bytes baked. This is the "why can't I just pull it when it's
running" milestone made real (over a configured provider).

## Context
Outbound Internet from the guest works only over a provider: `relay` (`?slirpRelay=<ws>` → wvrelay) or
`tailscale` (IPN worker + Headscale/Tailscale control), never the `offline` default (web/loader.js
resolveSlirpProvider). E3-T16 proved a 100 MiB `wget` through the relay; E3-T19 (guest-HTTPS /
provider hardening) is the flaky/blocked dependency — Docker Hub is HTTPS + bearer auth, so this task
rides on E3-T19 stabilizing. Registry pull is many small TLS requests (token, manifest, config, N
layers) — different from one big `wget` — so DoH name resolution, TLS session handling, and connection
churn through the provider are the real risks to shake out here. NOTE (memory): live proofs need a
fresh stack (`down -v` before each run) or Headscale flakes with NeedsLogin.

## Deliverables
- A documented boot recipe: which provider, URL params, and infra (a running wvrelay, or a
  Tailscale/Headscale control + auth key) needed to pull in-guest.
- A gated Playwright proof (like e3-t16/e3-t19): fresh profile → boot Alpine with the provider →
  `wvpull busybox` in-guest → assert the bundle lands + `wvrun /opt/containers/busybox` runs it
  (`CONTAINED_$((6*7))` from the freshly-PULLED image, echo-proof).
- Recorded numbers: bytes pulled, request count, wall time over the provider; the failure modes when
  the provider is down (typed error, no partial bundle).
- Provider-agnostic where possible: prove over relay first (simpler infra); tailscale as a second
  recorded leg or explicit deferral.

## Acceptance criteria
- [ ] Gated live test: browser VM booted with a provider pulls `busybox` riscv64 from a real registry
      in-guest (no baked bytes for it), digest-verifies, unpacks, and `wvrun`s it to the computed
      marker — the image ran was fetched over the network at runtime.
- [ ] Offline boot (default): the same `wvpull` fails with a clear "no network provider / connect
      refused" typed error and writes no bundle — honest, not a hang.
- [ ] Digest integrity holds over the wire: a tamper/lie is caught (reuse T06-T01's verify; if the
      registry can't be made to lie in the live test, prove it in the T01 mock and reference it).
- [ ] Numbers recorded (bytes / requests / wall time) + the fresh-stack discipline documented so the
      proof reproduces.

## Adversarial verification
Token expiry across a slow multi-layer pull (the interpreted guest is minutes-slow — tokens WILL
expire) → refresh, no 401 abort. Connection drop mid-pull → typed error, resumable/idempotent re-pull
(cache holds verified blobs). DoH/name-resolution failure → clear error, not a silent wrong-IP connect.
Confirm the pulled bundle is the REAL image (entry binary riscv64 ELF), not an error page saved as a
blob (HTTP-code check, like the sideload fix). Do NOT claim tailscale if only relay is proven — record
each provider's status explicitly.
