Scope and claim
---------------
`web/clipboard-service.js` provides the host-side service on top of the verified Channel. It
validates the shared 256 KiB UTF-8 contract, sends focused paste data as CLIP_SET before invoking
the caller's key-ready callback, never inspects clipboardData while the target is unfocused, and
never polls the asynchronous clipboard-read API. Guest CLIP_SET values write immediately when the
browser accepts them; permission failures retain one bounded value and expose staged/denied state
until a gesture calls flushStaged(). A two-entry direction/generation/content-hash history consumes
only the expected host-to-guest echo, so a different or expired identical copy remains a real copy.

Coverage map
------------
- guest CLIP_SET writes when allowed, stages denial, and flushes only from a gesture: immediate
  permitted write, bounded staged value, honest DENIED UI state, and successful gesture retry.
- focused paste sends CLIP_SET before the key-ready barrier and unfocused paste never reads data:
  capture ordering, capability option, preventDefault/stopImmediatePropagation, and a clipboardData
  getter spy that remains untouched while focus is absent.
- host and guest directions use bounded, generation-aware echo history: same-content expected echo
  suppression, different-content delivery, expired identical-content delivery, and history <= 2.
- paste and guest payload limits reject without reading the asynchronous clipboard API: exact rejection
  for 257 KiB and invalid UTF-8 with no frame or host write.
- gesture listeners are idempotent and detach preserves the caller-owned Channel: one paste/gesture
  listener set, one retained staged value, and clean removal without closing transport state.
- channel generation changes invalidate a stale expected echo: reconnect generation cannot suppress a
  copy from an older transport.
