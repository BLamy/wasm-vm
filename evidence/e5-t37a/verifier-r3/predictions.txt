SAFETY (the central question; any counterexample refutes)
Definition used: a reported wait (take_idle_wait_nanos() == Some, or run returned early) is FALSE
if, with the host clock frozen at its value at the report and no host call other than run(),
the guest takes an interrupt (or the machine raises one that is enabled) before guest time
reaches the reported deadline.
S1  Behavioural probe: at reported waits in my lockstep runs (guests with CLINT only; with a UART
    that really has RX work, FIFO trigger 8 and 1, IER on/off; with an RTC alarm; with PLIC
    enable/complete stores placed in the wfi's block), a yield-off machine in the identical state
    run for >= 30,000 further work slots with the host clock frozen takes ZERO interrupts.
S2  UART RX byte pushed by the host BETWEEN run calls, receive interrupt enabled: the next run
    call does not report a wait until the character-timeout or trigger interrupt has been taken
    (0 reports while `uart.tick()` would return true).
S3  UART THRE (IER.ETBEI set, THR written in the wfi's block and in an earlier block): no wait is
    reported while the THRE interrupt is deliverable.
S4  RTC alarm armed in an earlier block of the same call (marker must be dropped by the fabric
    touch and stay None while armed): no report until the alarm has fired and been cleared.
S5  virtio: a queue with work and a host config-change request latched by
    sync_backend_config_irq (set between run calls): the first boundary of the next call computes
    idle = false, so a `wfi` in that first block is not reported; the interrupt is taken first.
S6  Every interrupt level the boundary writes is in fresh_mip: K1 above, plus no other writer of
    `mip` exists at a boundary (grep set_mip_bit / write of W_MIP: only sync_clint, sync_plic,
    sync_sbi_timer, CSR instructions and trap entry).
S7  Stale marker across a host push: marker Some at the early return; the host then pushes a UART
    byte / injects a key and calls run() -> marker is None at entry, so the new call cannot report
    a wait before a full pass has seen the device. (take_idle_wait_nanos() called AFTER such a
    push and BEFORE the run is the round-2 follow-up; I will measure and report it, and judge it
    against the task's text.)
S8  Restore paths: every public restore entry point (load_resume, load_accelerated_resume,
    restore_desktop_snapshot, restore_recording_branch) leaves take == None and accounts no wake.
    A path that restores guest state without clearing idle_wake_pending trips the
    debug_assert in paced_wake or moves the restored guest's mtime -> refuted (Boundary: "a
    restore drop[s] it").

COMPLETENESS (may be imperfect; must not be vacuous)
C1  Call starting at the post-wfi boundary (the realistic flow: run returns early, host sleeps,
    run again with a large budget), idle loop of several blocks: EVERY such call returns early at
    the next waiting `wfi` and reports, in all three loops. Yield count == number of calls.
C2  Call starting at an arbitrary block boundary: reports at the first waiting `wfi`.
C3  Characterisation: the only unreported true waits are (i) the call sampled no block boundary
    before the `wfi`, (ii) a device had work at the last full pass, (iii) a fabric access since.
    Prediction about (i): a host that always runs ONE work slot per call never gets a report from
    a guest whose `wfi` is not the first op of its block (the Boundary's "picked up at a later
    wfi" does not happen for that host); with batching off it always does.
C4  Not vacuous with ordinary devices attached and idle: a machine with PLIC, UART (driver-style
    setup: FIFO on, IER RX on), RTC (no alarm), and the virtio slots (blk, rng, net with an idle
    backend, input, console as far as they can be attached in a unit test), all idle, reaches
    marker == Some at the first boundary and reports the wait. If some ordinary attached-and-idle
    device keeps the marker None forever, that is a finding to quote against "Measured on the
    idle Replay desktop, the devices were idle at all 1,050 of 1,050 wait checks".

LOCKSTEP PREDICATE I will use (written before reading either harness's scratch patch)
  must_yield(wfi just retired by the subject's call) :=
       stale mip & mie == 0 at the wfi                       (pre-existing guard)
    && nearest future deadline exists and the pacer's ceiling is below it
    && the levels msip, mtime>=mtimecmp, (SBI) mtime>=stimecmp, PLIC eip(0)/eip(1), each gated
       by mie, are clear on the CONTROL machine after the same wfi
    && the subject's call has passed at least one sampled block boundary before this wfi
       (tracked by the harness from the control: a slot of the current call began with the
       control at a block boundary — pre-existing `at_block_boundary()` — or batching is off)
    && at the last such boundary no device had work and no fabric access happened since
       (harness-side: the pre-existing fabric_epoch counter sampled by the harness at the
       control's block boundaries; device work decided from device state: UART rx pending /
       timeout running / irq level, RTC alarm armed).
  The harness asserts BOTH directions: yield => must_yield (no early return otherwise) and
  must_yield => yield (no missed return).
