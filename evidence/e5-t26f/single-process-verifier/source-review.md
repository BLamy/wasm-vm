## Explicit stricter refusals and domain limits

- Numeric values now have machine bounds: PID/parent/FD at INT_MAX, stat/I/O/fdinfo numbers at their checked limits, flags at u32. The old shell accepted some overlarge decimal/octal strings. These cannot be valid values from the fixed kernel fields being observed; no proof guard is removed.
- C rejects embedded NUL/non-ASCII control data, stops with a 4,097-byte witness, caps FD enumeration at 4,096 entries, and fails on any enumerated FD stat error. The old shell's capture bound was postcapture and its inode tests could skip inaccessible unrelated FDs. These are explicit fail-closed restrictions, not an assertion that arbitrary proc workloads fit these limits.
- Numeric parsing/serialization can normalize noncanonical leading-zero PID/start/owner values that the shell compared textually. Accepted-byte equivalence is for the fixed canonical proc domain, not every artificial text string the old parser could accept. The physical player and owner identity predicates remain numeric and mandatory. Non-proof PCM timestamp/availability values retain their single-token informational treatment; duplicate keys still refuse.
- Testmode proc paths/inodes are controlled. Real parent/close/write transport is separated from fixture-backed process/PCM facts. No mock tree or native ARM result proves a prepared RV64 player, browser speedup, timing cause, or helper promotion.
