## Predictions to test after freeze

Each prediction starts untested. A later result must cite frozen source lines, the concrete test case or raw JSON path, and artifact hashes. Expected behavior below is a falsifiable obligation, not a claim that evidence already holds.

1. **P1 — preservation of the old contract.** The old buffered helper/tests remain intact. A hunk-by-hunk comparison of the separate new shell wrapper with that held baseline will show the same two matching pre-save observations, arming requirements, finite payload, feed/close, wait for the actual original child, three observation `printf` calls, and conditional success/failure markers. Controlled old/new observations using identical proc bytes and identities will produce byte-identical accepted observation values and terminal output, including available I/O lines and the unavailable-I/O case. Any new stricter refusal will be named and justified against fixed kernel text; it cannot silently stand in for equivalence. No full legacy injection into the real guest is required.

2. **P2 — actual parent and FD3 ownership.** The shell invokes the observer through command substitution with `exec`, so C's libc `getppid()` identifies the actual supervising shell instead of an intermediate process. A caller-supplied numeric parent alone cannot authorize observation: actual parent, shell-owned player parent, and selected proc paths must agree. C closes its inherited FD3 before observation while the shell's descriptor survives with its original inode/access mode. A controlled subprocess test will observe both sides and prove that successful observation leaves the parent's finite feed functional. Wrong/reparented caller or player refuses before feed; observer failure cannot leave an extra FIFO writer or allow a green completion. These tests must execute the real wrapper/process topology, not mock `getppid()` as the happy-path authority.

3. **P3 — identity checks remain sufficient.** The observer checks actual PID, expected comm/state, start time, executable inode and parent using fixed proc paths, then repeats the identity check after acquisition. Controlled changes of PID/start/parent/executable or disappearance between reads must refuse. Invalid PID arguments, truncated/surplus stat fields, and token shifts must not select a different process or field. The result is bounded consistency across observations, not a new claim of atomicity across all proc files.

4. **P4 — descriptor and PCM guards survive.** One actual read-only child FIFO descriptor, one correct parent FD3 with the required access flags, exactly one PCM descriptor, `pipe_read`, matching PCM owner, `PREPARED`, and zero hardware/application pointers remain mandatory. Wrong inode/type/mode, duplicate/missing descriptors or fields, extra writers, nonzero pointers and wrong state refuse. Duplicate-key refusal covers every fdinfo/PCM key, not just whichever required key happens to be extracted first. Unknown ordinary metadata retains the held parser's permitted behavior or receives an explicit stricter-format justification. Real proc inode/link checks cannot be replaced with string/path equality.

5. **P5 — bounded acquisition and strict parsing.** Fixed-size reads handle ordinary short reads and interrupted reads without accepting an incomplete record. An error after a successful prefix, premature EOF, overbound suffix, embedded NUL, malformed separators, surplus values, duplicate keys and numeric overflow fail closed where the frozen proc grammar requires it. The EOF-only `pipe_read` format and newline-terminated records retain their distinct rules. All seven I/O values use strict unsigned decimal grammar; all required basic fields and the permitted complete accounting group are checked, with original line bytes preserved for serialization. No minus exception is inferred from cancelled-write accounting's negative effect. Test fixtures use unique immutable filenames to avoid the prior host/Colima inode-rewrite artifact.
