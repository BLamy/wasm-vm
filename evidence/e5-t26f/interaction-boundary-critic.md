## Boundary finding

The current timed path performs a complete post-restore observer run before feeding PCM: `e5_play` reacquires identity/FD/PCM state, compares it with the saved record, prints three lines, then feeds and waits ([helper lines 112-135](../../tools/guest/e5-t26f-resident-observer.sh#L112)). The observer stats the executable twice, reads process stat/wchan, enumerates child and parent FDs, reads PCM status and process accounting, and rechecks identity ([C lines 219-280](../../tools/guest/e5-t26f-observer.c#L219)). Those checks materially answer PID reuse, failed/replaced child, restored process state, FD ownership, and prequeued PCM concerns; retaining them is conservative. The three `printf` calls merely render their already-accepted values ([helper lines 67-74](../../tools/guest/e5-t26f-resident-observer.sh#L67)). The two pre-save printed observations remain unchanged and establish PID/start/executable/parent/FIFO/PCM/PREPARED/zero-pointer state before the authenticated checkpoint ([helper lines 90-103](../../tools/guest/e5-t26f-resident-observer.sh#L90)).

The browser wrapper also explicitly selects a diagnostic JIT/residency arm ([wrapper lines 61-64](../../tools/verify/e5-t26f-browser-single-process-observer.mjs#L61)), causing an awaited `jitBefore` RPC inside the original clock ([runner lines 1725-1731](../../tools/verify/e5-t26f-browser-roundtrip.mjs#L1725)). That acquisition is likewise not a task criterion. Later JIT/report collection is correctly after the frozen end ([runner lines 1869-1909](../../tools/verify/e5-t26f-browser-roundtrip.mjs#L1869)).

The existing evidence does not show that suppressing the print is enough: the 05b record first observes fresh PCM at 4,358.600 ms and ends at 4,362.200 ms ([raw lines 466-505](single-process-observer-05b82bc6/reuse/failure-post-restore-interaction-checks.json#L466)); the separate sampling run first sees PCM at 3,355.900 ms and the marker at 4,248.325 ms ([latency raw lines 2468-2505](single-process-observer-05b82bc6/latency/record/failure-post-restore-interaction-checks.json#L2468)). These locate the print ahead of PCM but do not quantify its exclusive cost. The old quiet-text result used the 20-process `2ae65408` helper and failed at 4,877.610 ms; it proves the oracle, not new-C-plus-quiet latency ([quiet review lines 23-49](resident-verifier/quiet-text-results.md#L23)).

## Minimum proof if post acquisition is considered later

The original boundary question still has a narrow answer: post `/proc`/ALSA acquisition is not textually required by the task, but removing it would discard useful identity authority and is a broader hypothesis than suppressing prints. Only if the conservative screen fails or later evidence motivates that broader change should a future fixture test whether dual pre-save identity plus authenticated whole-machine restore and trace-backed completion can replace the pre-feed post observer. Its acceptance record would need all of the following in the same unprofiled browser execution:

1. **Prepared identity and exact restored state.** Retain two matching pre-save observations of the actual child: PID, start time, physical parent, executable inode, unique read-only FIFO FD, parent writer FD, PCM ownership, PREPARED, and zero pointers. Bind those observations, helper/image/browser/runtime hashes, and the exact snapshot SHA. Re-run the existing snapshot parser checks for prepared parameters, no pending transfer/bytes/event/TX kick/reset/release ([proof lines 102-160](../../tools/verify/e5-t26f-resident-proof.mjs#L102)). On restore require the same snapshot SHA, first-present CRC, resume receipt/overlay generation, and no `booting`; additionally retain a guest trace or authenticated lifecycle/state digest showing the restored CPU/process state resumes from that checkpoint rather than merely trusting printed shell variables.

2. **PID-reuse and failed-child falsification.** Record that the restored shell's `wait` targets the saved child identity and returns zero, with no intervening fork/exec by that parent. A guest lifecycle trace containing parent/PID/start (or an equivalent kernel-state digest before feed and at wait) is the narrowest independent check. Run one killed-child sabotage: it must produce no green success and must fail feed or wait. A numeric PID alone is insufficient because it does not exclude reuse; a post-run `/proc` lookup is also insufficient because the successfully waited child has exited. The source's conditional wait remains necessary ([helper lines 121-135](../../tools/guest/e5-t26f-resident-observer.sh#L121)).

3. **Fresh, non-stale PCM.** Preserve the parsed checkpoint's empty TX state and two post-restore, pre-gesture locked/suspended zero-ring samples ([runner lines 1752-1775](../../tools/verify/e5-t26f-browser-roundtrip.mjs#L1752)). Bind the finite payload source, freeze the pre-command write index, then before the timed end capture the expected positive written-frame delta with non-silent frames, output attachment, and rendered-frame advance ([runner lines 1800-1869](../../tools/verify/e5-t26f-browser-roundtrip.mjs#L1800)). A stale/prequeued sabotage must fail. No unrelated PCM-fidelity requirement is added.

4. **Physical interaction evidence.** Keep the delayed physical mouse down/up, a post-T0 tablet frame and rendered cursor at the requested coordinates, accepted host focus, and no held button ([runner lines 1763-1799](../../tools/verify/e5-t26f-browser-roundtrip.mjs#L1763)). Physically type `play`; explicitly assert the expected ten DOM/guest keyboard transitions and `inputSequenceMatch`, then require guest-visible pixels and the conditional completion marker. The recorder computes the frame/event match but acceptance currently does not include it ([terminal lines 873-915](../../web/desktop-terminal.js#L873)), so the future proof must assert it rather than merely serialize it.

5. **Unchanged clock and perturbation control.** T0 remains `firstRestore.completedAt`; the end remains the first timestamp after cursor/focus, physical typing, fresh fixture PCM, rendered-frame advance, and successful same-child wait. Assert `end - T0 <= 2000` exactly as today ([runner lines 1924-1937](../../tools/verify/e5-t26f-browser-roundtrip.mjs#L1924)). No observer, verbose terminal report, JIT/CPU/latency RPC, profiler, screenshot, or collector may run before that end. A source/guest-trace audit must demonstrate that absence. Diagnostics may report the already-captured structured facts afterward, but a separate diagnostic replay cannot establish identity for the timed execution.

If such a broader rescheduled-fixture record and the three bounded sabotages (killed child, PID/lifecycle mismatch, stale/prequeued PCM) hold, the original prepared-child/no-reboot/fresh-interaction claim remains independently falsifiable without post acquisition. That is not the recommended first move. Until a durable print-only candidate passes the unchanged cap and full acceptance path, the preserved 4.3622-second failure controls and F remains unproven.
